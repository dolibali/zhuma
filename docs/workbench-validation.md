## 真实模型调用

用户授权的 DeepSeek 配置通过官方凭据服务写入隔离测试环境。模型列表与最小请求均返回 HTTP 200；规划实际路由为 `deepseek-official / deepseek-flash`。凭据不进入工作台数据结构、源码或本文。

1. 订单筛选与 CSV 导出：通过页面建立项目、两名真人、界面/质量专家和四项资产，再创建任务并调用规划。初始提示词产生了八项实现细节追问；修改为仅追问阻碍编排的关键问题，将实现细节交给合适节点确认。重启 Host 后重新调用，单次返回六节点、零前置问题：业务确认 → 接口契约 → 前后端并行 → 独立测试 → 产品验收。执行者、评审人和资产引用来自所选目录，包含分工依据与输入输出。页面审阅后应用为草稿，仍可修改并另行确认。
2. 缺少财务审批人：任务只选择界面专家，明确要求两名不同真人完成核验和审批。模型首次返回带未分配节点的提案，被完整性校验拒绝；一次定向修复后返回三项问题与空工作流，未编造人员或权限。页面“应用草案”不可用，原任务未被替换。该例仅测试角色缺失识别，没有金融操作。

以上是两个有代表性的真实场景，不能推导为所有行业、复杂工作树和模型均已达到规划质量要求。原始请求/结果保存在隔离测试环境的 planning audit，未提交仓库。历史八问审计仍可读取，新规划限制最多三问。

## 浏览器与 Host

通过 Playwright CLI 在真实 DSH 浏览器中操作：

- 项目、成员/专家、资产定义、任务和参与者实际创建并持久化；服务重启后重新打开仍可读取。
- AI 提案在主区展示，可应用、继续修改 Skills 和多位评审人；磁盘验证同一节点保留两个 Skill 和三位评审人。
- 工作流节点拖动后保存坐标；删除一条依赖后重新连接，边数由六变五再恢复六；反向连接形成环时被拦截。
- 确认为 v1 后继续编辑，新增两层子工作流；完整工作树显示八节点与两条拆分边，点击能定位所属工作流。移除子工作流保留父节点。此处验证的是嵌套草稿，尚无独立子任务权限与调度。
- 移除仍承担节点/评审的参与者时，弹窗内直接显示重新分配提示。
- 通过文件选择导入 Markdown 资产定义，预览原文后保存，磁盘中能读到对应定义；输入和选择控件使用独立关联标签，长文本不污染控件名称。
- 匿名 POST 到实际 `/api/zhuma/snapshot` 返回 HTTP 401。该结果仅证明本地 Host 拒绝匿名，不替代多人权限验收。
