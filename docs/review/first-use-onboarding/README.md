# 首次无模型使用：发行配置切片

工作项：[#38](https://github.com/dolibali/zhuma/issues/38)。本记录针对固定 DSH `687f282e8625c6b8d11ff58211a90524be2e4317` 和 Zhuma 发行组合；真实界面验收另按精确构建版本记录。

## 机制与实际问题

DSH `ui-settings-models` 默认启用 `credentialOnboarding`。Host 把这个公开布尔配置写入页面 bootstrap，Client 在无可用模型时自动显示凭据步骤；用户选择稍后配置只结束**这次**步骤，未形成持久的“不要自动提示”偏好，因此刷新后仍可能再次显示。手动建项、浏览及人工交付不需要先配置模型，却在首次进入时被这个步骤打断。

DSH 的 Preview Notice 是另一项按文案版本持久确认的公告，不能与模型配置合并，也不能借本次修改跳过。语言由官方 `locale.preference` 及系统／浏览器语言解析；其中文、英文词典与设置中的语言选择均已有现成生命周期。测试浏览器是英文时出现英文宿主文案符合该机制，不能据此把每个人的语言偏好强制改成中文。

## 采用与边界

发行组合将 `ui-settings-models.config.credentialOnboarding` 设为 `false`。DSH Client 在自动路径直接结束凭据步骤；模型设置页、主动打开凭据配置、凭据读写、Preview Notice 和语言偏好继续由官方实现管理。本仓不存第二份“已跳过”或语言状态，不读取密钥，不调用付费模型。

需要模型的规划仍是用户显式操作。模型不可用时保留真实错误与已保存的任务草稿；本切片不将配置缺失伪装成规划成功，也不更改执行权限。Zhuma 工作台当前仍以中文静态文案为主；英文偏好下的全页翻译不由该发行配置解决，不把官方弹窗随语言变化误称为 Zhuma 全页双语完成。

## 验证

作者校验发行补丁在固定上游的配置键和 schema 中存在，并运行仓库检查与构建。正常界面的首次进入、刷新／重开、设置主动打开、显式规划失败及中英偏好、浅深主题／桌面窄窗与缩放／键盘效果交由协调在同一构建字节上另验，未执行前不写为通过。

协调曾用 360×800 压力视口检查设置页，发现官方桌面双栏被挤压；该尺寸不是本桌面产品的首版支持范围，不能据此阻断本次无模型引导切片或引入手机专项样式。桌面窗口和缩放的验收口径以[共同 UI 设计](../../ui-design.md)为准；真实桌面窗口若出现可操作性问题，再按该场景作有界修复。
