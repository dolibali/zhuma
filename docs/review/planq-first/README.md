# A-PLANQ 首批验证

无 UI 布局／控件变更。本批在已有可编辑提案链路改进候选输入及校验，未启动模型、MCP 或节点执行。

`tests/fixtures/planning-scenarios.mjs` 固定八类业务目标：[上下文捕获数据](context-cases.json)由当前构建的真实 `buildPlanningContext` 执行产生。公开虚构数据，不是模型输出。每例包含一个相关资源和一个无关对照，人工期望如下：

| 场景          | 期望资源／分工与交接质量评估点                           |
| ------------- | -------------------------------------------------------- |
| CSV 导入      | 字段映射 Skill；业务确认缺失字段策略，映射结果供实现使用 |
| 报表脱敏      | 脱敏 Skill；权限判断交由人，独立验证角色可见范围         |
| 登录 API      | 接口规范 Skill；接口输出与调用方一致、独立评审           |
| 公开市场研究  | 数据 MCP 候选；未知授权不宣称可访问，结论附来源          |
| 采购原型      | 原型设计 Skill；界面产物可审阅，交互决策有负责人         |
| 版本发布      | 发布模板候选；不宣称已经应用，交接含发布／回滚信息       |
| 文案校对      | 校对 Skill；不强制多 Agent、多层流程或工具               |
| API／SDK／Web | SDK 资源；真正依赖前置约定，可并行部分并行，再汇合验证   |

当前只验证第一列目标对应的资源候选；第二列中的模型分工、语义交接和拆分质量均保留 **未运行**，JSON 中相应评分为 null。不能用手写响应或检索命中代替模型质量。

定向命令：

```bash
pnpm build
node --test packages/agent-core/tests/planning-quality.test.mjs packages/agent-core/tests/workbench.test.mjs packages/dsh-adapter/tests/workbench-service.test.mjs
```
