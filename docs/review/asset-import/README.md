## 用户路径与设计依据

团队资产 → 导入定义 → 选择文件、目录或 ZIP → 勾选所需定义 → 核对正文／文件／缺项 → 编辑名称及分工、选择新建或明确更新 → 导入。缺少来源文件或默认 Skill 的定义保持停用；取消不写入。专家在资产和成员入口使用同一 Participant ID，默认 Skills／MCP 与节点配置复用搜索多选控件。

依据 Agent Skills 的入口和附属目录、OpenClaw 的人格／方法文件划分做静态映射，具体主来源在[格式说明](../../asset-import.md#格式与边界)。采用“先预览、明确目标后保存”，避免选择 ZIP 就安装或覆盖。私有文件按路径先排除；这不等于内容级隐私识别，也不是外部运行时兼容承诺。沿用现有中性主题、弹窗、选择器和官方桌面，不新增资源平台或执行循环。

## PR19 复核修复：常见凭据文件在读取前排除

[独立复核](https://github.com/dolibali/zhuma/pull/19#pullrequestreview-5623996053)发现 .npmrc／.netrc／.git-credentials／.pypirc 未进入共享私有路径规则。新增合成占位负例后，旧代码的两个核心／Host 回归均失败；目录浏览器回归出现“Private file must not be read”，说明实际进入了 arrayBuffer。ZIP 的私有条目使用错误 CRC，旧代码因读取并解压它而失败。

修复提交 `39f4a2d4855a983a0c472f91e0e1e1b37c383dbe` 只扩充共享文件名排除规则，任意层级和大小写均生效。16 个合成路径覆盖包根、目录根、Skill 内与嵌套目录；直接 files 和 ZIP 均标作忽略，不进入 preview.files、origin.filePaths、存储版本或来源返回值。浏览器对目录内全部新增路径禁止 arrayBuffer，并确认预览载荷字节为空。普通 .editorconfig、package.json、schema、许可和原脚本数据仍保留，不增加内容扫描。

修复后 `pnpm check` 183/183、`pnpm workbench:build` 及导入浅深专项 8/8 通过。上文 181/58 与原生 JSON／截图仍对应首批构建，不能认证修复后构建的原生运行；本次没有重跑无关桌面主题、拖窗或 B 身份链。没有可见布局变化，保留首批对照图。本次不追溯擦除旧来源包，历史数据迁移及清理仍未实现。
