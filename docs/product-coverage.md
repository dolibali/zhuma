# 产品能力覆盖账本

## v1.3.0 范围增量

已发布 v1.2 的成员、本地执行、固定交付、评审和下游能力保留。[v1.3.0](release-v1.3.md) 增补固定 RC.4、多执行器、团队资产／文件与发布版本、会话布局；这是本轮范围，不是已通过结论。个人专家独立使用、用户 MCP、其他 CLI 完整资格及原高级范围仍后置。准确阶段、阻塞和验收只见 [#310](https://github.com/dolibali/zhuma/issues/310)，不以旧版契约或安装结果认证新代码。

## 首个 v1.0.0 的范围裁决

用户已确认首个 v1.0.0 按核心闭环收口：账号与项目任务规划 → 本地 Zhuma 持续执行（模型／Skill）→ 固定正文／文件 → 人工／Agent 评审 → 下游读取与项目成果。真实模型、正常成员界面及安装／恢复按各自退出条件验收，代码合入或契约通过不等于发版完成。

非空 MCP 连接、资产／工作流发布版本、批量反馈、复杂子流程及效能统计转为后续版本；个人专家直接使用和外部 CLI 继续保持原后置安排。这些能力保留范围、既有分支／合同及退出条件，不标完成、不删除；完整 FR／大 Issue 尚未齐的条件不冒充关闭，也不再全部作为首个 v1.0.0 的发版阻塞。详见 [v1.0.0 范围与验收说明](release-v1.0.md)，实时派工仍以 #25 和对应工作项为准。

## 完整产品范围与证据

以用户最后确认的原型主要功能和开发需求 FR01–17 为范围基线；具体页面、控件和布局可依据真实任务与业界实践重做。本表保留注明版本的实现／证据和退出条件，不维护实时交付阶段。规则与总索引见 [#25](https://github.com/dolibali/zhuma/issues/25)，阶段、优先级、依赖与阻塞读取各行工作项及其标签，Project 仅作总览。字段、目录 CRUD 或测试数不能替代完整用户结果。

覆盖标记只描述能力和证据边界，不对应 Issue 的 stage：**部分**表示有切片但完整退出条件未齐；未验证的运行结果不计通过。工作项合入也不自动关闭 FR 或产品验收。已发布但未集成的模块保留候选身份，不能写成已集成，也不能忽略已有实现。

## 交付约束

Agent整体能力采用[长期机制/成本/主责对照](architecture/task-session-delivery/design.md#agent-能力对照与证据边界2026-10-25)、[正常会话交互](ui-design.md#agent-工作会话补充队列与协作设计要求待真实接缝)和[专项证据门槛](architecture/task-session-delivery/test-plan.md#agent-专项场景2026-10-25增补待执行)：运行中Steer/下一轮Queue、定向通信、按需固定输入、全Agent串并行/独立评审均保留于原FR07/08/10/13及LC范围。它们是设计/验收要求，旧执行切片和原23行为不认证新增能力；实时顺序/阻塞继续只看[#25](https://github.com/dolibali/zhuma/issues/25)、[#35](https://github.com/dolibali/zhuma/issues/35)与各关联工作项。

- 继续删除独立 Rules 资产/配置、独立讨论页、单独“多层演示”专区、强制冗余验收面板。后台必要版本/权限/完成条件不等于恢复这些页面。
- 主要能力暂缓必须保留本表中的主责、依赖和退出条件；只改视觉不关闭业务条目。

- 验收主线是创建目标→计划→分配→人工或 Agent 处理→文字/文件交付→多人评审→退回修改或下游推进。目录与图编辑不能替代这条链。
