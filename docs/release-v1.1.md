# v1.1.0 范围与验收说明

本文保留 `1.1.0` 的历史范围与入口，不描述当前候选；当前范围见 [v1.2.0 说明](release-v1.2.md)。候选构建、源码或契约通过不等于正式发布。实时交付与准确版本的验证结论仍以 [#25](https://github.com/dolibali/zhuma/issues/25) 和 [#263](https://github.com/dolibali/zhuma/issues/263) 为准；已验 main、tag、来源清单与 Release 资产由协调者一次收口，既有 tag 不移动。

## 成员与任务

- 正常注册与登录使用原身份服务；共享后端保存成员、团队、项目、任务、固定交付和评审事实。模型凭据与原生会话保存在成员本机。
- 团队工作台支持项目、任务列表／看板、参与真人与专家、可编辑 AI 提案和手动工作流。已确认计划独立于草稿；新团队的公开基础专家、默认模板和工程 Skills 使用原资源版本及许可。
- 模板可以复制后编辑节点与角色，再补齐所需能力、保存并确认。团队知识按权限搜索、读取、起草和人工发布；Agent 起草权限独立于执行，只有真实接口和本轮明确许可就绪时启用，默认关闭。

## 共享任务在本机逐节点执行

1. 操作者启动同版本本地共享后端。成员在官方桌面选择后端，通过正常成员入口登录并进入自己的团队。
2. 负责人确认计划，再从“我的工作”开始原计划执行。分配给成员的实际工作项出现在“需要我处理”；成员可以手工提交，或主动点击“使用 Agent”。
3. 每个节点由成员明确选择本机模型和执行者。需要文件工具时，选择官方侧栏已经登记的工作区及只读／可编辑权限；上传本机成果还须独立添加允许交付的相对文件或目录。目录选择本身不允许把所有文件发给团队。
4. 本机使用原 Harness Agent、工具与持续会话。任务和侧栏工作区打开相同 Session；查看历史、刷新、重新登录、重开应用均不自动启动或恢复执行。重开后本次目录权限不会自动恢复。
5. 产物走原固定提交、评审和下游输入路径。全部指定评审人通过后，后继工作项才解锁；后继节点仍由负责成员主动启动。

新运行从原模型公开元数据读取配置额度，应用默认输出预算最高为 16,384 tokens；配置额度或已披露上下文容量更低时按更低值，未知时保留 4,096。该值是本次请求的预算，不承诺生成长度，也不改变已冻结运行或同会话后续消息的模型配置。

在“使用 Agent”的本轮配置中可选择当前空间的知识库；“允许 Agent 创建知识草稿”默认关闭。选择和许可仅绑定本次已受理运行，普通历史浏览和重开应用不继承写入许可。Agent 可按需搜索、读取已授权知识；允许起草时也只创建草稿，仍由人在知识页面发布。

用户已明确把**跨设备自动接续整条工作流留到下一版**。本版本不向共享任务提供全流程自动运行按钮，也不把共享后端代跑解释为成员本机执行。既有同 Host 的本机自动工作流保留。独立成员 Web 提供共享业务与人工交付；本机模型、目录和原生控制只在具有本机所有者权限的官方桌面开放。

## 交付、评审与恢复

文字、链接或真实文件形成固定提交版本。评审查看该版本正文及可授权预览／下载的文件，意见随该版本保留；退回后修改并重提，已接受版本才供下游读取。Agent 专家评审必须在同一本机原生 Owner 中读取固定目标并提交原裁决，后端不替成员执行模型。

共享后端须同时启用 `--file-uploads --independent-reviews`，服务会核对原材料目录与文件存储是否就绪。“Agent 评审”从本次固定提交进入，选择本机模型和服务仍允许的指定专家后开始。多位专家各有独立评审：上一位资源已排空且刷新后还有可启动候选时，可明确选择下一位；已提交意见保留，失败或取消不自动获得同一专家的新尝试资格。

从工作区侧栏打开原评审 Session 只读取历史与状态。结果未知、资源仍占用时，可明确停止评审或核对并恢复结果；停止未确认时重试保留原请求，普通打开不自动恢复、重投裁决或启动模型。

运行请求已接收、模型已停止、资源已排空、成果已提交与评审已接受分别以原事实呈现。注销和撤权立即禁止新工作；在途受理和独立清理须保留真实义务，未知回执不能解释为没有 Run，也不能据超时释放写权或自动换设备重跑。正常关闭、同盘恢复、既有任务 Session 和工作区关系均按最终候选独立验证。

## 发行与后续范围

本轮仍以 macOS Apple Silicon（arm64）候选为验证对象；签名、公证、自动更新及其他平台状态以准确发行说明为准。未认证的平台不因源码编译通过而进入支持列表。共享后端当前为本地部署，集群部署后置。

非空 MCP、跨设备自动工作流、复杂子流程和完整工作树执行、资产／工作流发布版本、批量评论反馈、效能统计、个人专家直接使用和外部 CLI 继续保留到后续版本。后置不代表删除功能范围或关闭对应工作项。

最终验收须分别记录正常成员桌面、真实供应商与 Skill、同工作区同 SID、实际文件内容和摘要、独立 Agent 评审、退回重提、下游输入、注销／停止及冷恢复。两进程、合成端口、传输契约和真实 SDK 无模型测试各保留其证据边界。
