## 正常入口

官方侧栏在“团队工作台”下方增加“专家”。打开后直接搜索名称、职责或能力，按已有职责筛选；左侧选专家，右侧查看完整工作方法、默认 Skills／MCP 和来源。列表、成员页、资产页复用同一 Participant ID，不复制身份或创建另一份资源库。

新建、编辑、短文字或目录／ZIP 导入沿用已有表单与 Host 命令。保存失败保留草稿和请求 ID；成功后清除筛选并定位同一专家，取消不写入。专家入口的导入必须包含并勾选专家，配套 Skills 可一并导入；单独 Skill／工作流引导到团队资产，错误包不会留下可误提交的旧预览。导入后的方法与来源仍只读，更新正文走显式重新导入；本地定义可编辑。

重新选择文件时先作废旧预览、勾选、版本及失败重试请求，再开始读取；大小超限、文件读取、文字格式或 Host 预览失败都不能提交旧包。迟到的旧读取／响应也不能恢复旧预览、清除当前错误或覆盖新选择，新的有效包仍能重新导入。此规则同时作用于团队资产入口。

“可参与／已停用／待补齐”描述定义状态，默认 MCP 仍只是能力引用，不是运行连接状态。没有虚假的“使用”按钮，也没有通过创建团队任务替代个人直接会话。浏览、筛选、刷新、来源查看和定义保存不调用规划或启动模型。

## 共享 UI 和接入边界

新增 ExpertBrowser 只负责同一目录的筛选、选择和详情。WorkbenchPage 复用原来的读取、幂等保存、成员表单、默认能力选择器、来源窗口与 AssetImportDialog；普通工作台仍默认进入任务清单。侧栏注册复用已有官方 layout／slots，不新增原生壳、主题状态或业务数据库。新样式仅作用于专家目录，沿用现有字体与中性主题。

当前仍是单个本地 owner，入口命名为“专家”，不标作已经隔离的“我的／团队”。查询仍通过现有工作台 API；后续 S1 的五个 exact 入口门禁同样适用于此页，不能为了专家入口公开全量目录。B 提供可信身份／空间／运行事实后再接相应投影。筛选与选中仅为当前面板内存状态，没有实现账号／空间持久偏好。

设计研究参考 [Claude Code 的专家定义与能力配置](https://code.claude.com/docs/en/sub-agents)和 [OpenCode 的 Agent 配置与权限](https://opencode.ai/docs/agents/)：本批采用把可维护定义与实际调用／权限分开的机制。这里是官方文档研究与本产品设计选择，不是登录后竞品界面实测，也不声明兼容其运行时。
