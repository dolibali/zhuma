# v1.2.0 范围与验收说明

目标产品版本为 `1.2.0`，不是已发布声明。本页记录本轮范围、正常入口和证据边界；实时进度与阻塞仍以 [交付总索引 #25](https://github.com/dolibali/zhuma/issues/25) 和 [v1.2 工作项 #294](https://github.com/dolibali/zhuma/issues/294) 为准。源码、契约、真实 SDK、正常桌面、供应商调用和最终安装包分别按准确版本留证，不能相互替代。

## 本轮六项范围

1. **成员本机接续工作流**：从“我的工作”的已确认计划选择“运行工作流”，明确本机模型、工作区与允许交付的相对路径。共享后端保存原依赖与固定运行意图，本机只处理当前成员获准的节点；其他成员各自授权自己的 Host，离线时等待。原串行、并行与汇合依赖保留；当前桌面原生执行入口按并行额度 `1` 运行，不表示已验证多个本机 Agent 同时执行。
2. **自动交付、独立评审与有界返工**：文字与真实文件沿原提交协议形成固定版本；指定 Agent 专家独立读取该版本并评审。自动退回修改可设 `0`、`1` 或 `2` 轮，继续运行不重置已使用次数。真人评审进入实际待办；上限耗尽等待人工。全部指定评审通过且原运行收口后才解锁后继，无需评审的节点沿原固定提交接续。手工提交和逐节点“使用 Agent”继续保留。
3. **任务联合筛选**：团队任务按参与真人／专家、阶段、项目与搜索联合筛选，列表／看板使用相同数据、排序与计数；清除筛选回到原集合，空结果可直接调整条件。
4. **项目固定版本知识**：项目“资料与成果”关联已发布知识的准确版本，并区分必需／可选引用。运行沿原项目快照冻结引用，Agent 使用原知识工具按权限读取固定 page/version/checksum。引用清单、工具注册或 capability 不代表正文已读；必需正文实际读取及完成门禁须有独立业务证据。个人运行的选择与起草许可不扩大团队授权，自动节点不继承人工草稿许可。
5. **共享后端 AI 规划**：成员按任务目标、实际参与者、团队资产、专家与 Skills 请求规划；提案可预览、应用并继续自由编辑。模型可用性与配置提示来自实际后端，失败保留输入，不以模板或模拟成功代替供应商响应。规划模型由共享后端操作者在其官方模型设置中配置；桌面执行模型仍由成员在本机配置，两处不自动复制凭据。
6. **多成员停止、断线与恢复**：本轮按用户确认，以同一机器上的共享后端、两个隔离成员 Host／存储／设备身份，经真实 HTTP 验证接续、未知受理回执、停止及冷恢复。恢复保留原 Run／Session 与清理义务；普通查看不运行，未知回执不等于没有 Run，不因超时换设备重跑。该证据不认证实体第二台设备的网络、休眠或系统差异，也不替代真实供应商验收。

保留 v1.0／v1.1 的正常账号与团队、原工作区和会话导航、同任务同原生 Session、固定历史交付与下游读取。新安装与既有 profile 的模式、资料不自动互相迁移；[v1.1 说明](release-v1.1.md)保留为历史记录。

## 正常操作与运行位置

正常入口见[工作台操作说明](../distribution/workbench/README.md#正常操作)。共享后端按[服务说明](../distribution/server/README.md)启动并显式启用 `--file-uploads --independent-reviews`；成员从官方桌面选择该后端并正常登录。成员 Web 提供共享业务与人工交付，本机 Agent、模型及目录授权仍从官方桌面进入。

“运行工作流”是成员对本机处理范围的明确授权，不把全团队工作交给一个成员的凭据。人工节点可自行完成并输入文字或上传文件；提交给真人的评审必须等待真实操作。目录读写、文件交付与知识起草分别授权，打开任务、历史 Session、刷新或重开应用不自动恢复执行权限。停止和继续保留原运行意图、固定版本与返工计数，不另建事实库或隐藏调度器。

## 发行与验证边界

支持候选仅为 **macOS Apple Silicon（arm64）**；ad-hoc 签名、未公证，无自动更新。Intel Mac、Windows、Linux 未认证。共享后端为本地部署，K8s／集群与公开网络部署后置。

最终验收分别记录：正常成员桌面与失败态、真实模型与 Skill、同工作区同 Session、真实文件内容与摘要、固定知识实际读取、独立评审／返工／下游，以及停止／断线／冷恢复。契约 fixture 只标契约测试；同机隔离成员、真实 SDK 脚本 Adapter、正常 GUI 和真实供应商各保留自己的覆盖边界。这里列出的是验收要求，不据文档或版本号宣告通过。

最终来源按已验 topic 普通合入 develop、再普通合入 main 收口；不重写已交付历史。使用[原 Desktop Release 工作流](../distribution/desktop/README.md#调试窗口先验收正式包一次构建)，绑定准确 main 完整 SHA 与同 SHA 成功 CI，再为 `v1.2.0` 一次构建并核验 DMG、`SOURCE.json`、`SHA256SUMS` 及配套启动文件。版本元数据、PR 或开发构建不等于已创建 tag、封包或发布。
