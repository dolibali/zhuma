### 首条交接验收脚本（LC-T11）

此脚本用四个虚构测试账号：执行者、两名独立评审人及一名不属于任务空间的无权者；不改变 FR16 至少三账号/两团队的基础矩阵。在真实工作台的合法任务/节点及实际本地 workspace 运行。首个外部 CLI、版本/协议/能力、Host 构建 SHA、各段原生 ID/Run/世代、账号空间与文件基线均记录；fixture 不冒充真实运行。

1. 原执行者从“需要我处理”启动 Zhuma，在当前应用已打开 workspace 中登记工作会话；任务与 workspace 列表进入同页，完成两轮真实公开流/消息。普通打开、刷新、查看历史不调用模型。
2. 选择外部 CLI，预览交接清单。包含目标/验收、用户补充、结论、代码基线/diff、正文/文件快照、验证结果、未解决问题/评审意见；分别标出已接受前驱、候选草稿和聊天来源，核对版本/校验和/授权/预算。仅预览不启动任何 CLI 或额外模型。
3. 空闲时确认交接；另测活跃段的“停止并交接”。源真实停止/释放写权后目标才可写，时间线记录切换边界；第二条消息到目标原生会话。任务和工作会话位置保持不变，旧段只读。返回 Zhuma 时按验证过的恢复能力续接或开带来源的新段，不伪装共用一个 provider 原生 ID。
4. 实际收到的上下文逐项对应确认清单；资料中的伪指令不改变策略，未决授权/工具调用不被复用，凭据和私人完整历史不进交接、日志或公开 DTO。未知/缺失内容显式显示，不以虚构成功补齐。
5. 展示真实代码 diff、正文和文件内容并显式提交固定版本；两名独立评审人针对该版本评论，一人退回。原执行者在同一工作会话修改，可继续交接工具；需修改义务不丢，新提交开新轮，旧轮/旧版本操作被拒；全部通过才解锁下游并回写 A/项目最新已接受产物。
6. 提交后继续聊天、切工具或改源文件，已评审字节/校验和和评论锚点保持不变。无权账号从任务、workspace、交接清单和文件入口均被拒，不泄露路径/内容；换工具不提升任何角色权限。

必须另测：双入口重复/并发确认仅一次受理、不同内容同键冲突；源停止超时/拒绝/失联时目标不启动；目标缺安装/认证或启动失败保留源历史和可理解恢复动作；内容/权限/基线变动使旧清单失效；同目录第二写入者被拒或隔离；停止后、目标登记后和受理前后崩溃重开均不重复 spawn；旧段迟到流不能覆盖当前段。检查首轮/消息/停止/交接事件真实归属，分块历史读取不能充作实时流证明。

验收按纯契约、协议/假网关、真实 Host、真实模型、视觉/安装包分别记录。未获付费调用授权时真实模型仍未验收；不能将通过模拟的 LC-T11 直接写成完整链通过。其余四工具继续逐项 LC-T01–06/11，不要求首批同时完成。

## 2. 契约与状态测试、并发与恢复

- LC-T02/03：同一 requestId 重放只一次执行、不同内容冲突；两个入口同时发送不同消息有确定顺序；重连/重复/乱序事件能补齐且不重复显示。启动成功但挂工作区失败、已登记但 spawn 失败、启动中取消都有可恢复记录。
- LC-T03/05：停止与结果并发、停止超时/拒绝、旧 Run/旧世代/旧计划、旧轮次/重复评审均不能覆盖当前状态或越过评审；失败重试/退回重提保持需修改义务。
- LC-T03/06：断网、渲染器刷新、Host/CLI 崩溃、重启、关闭再打开；没有真实回执不标完成/取消；历史读取不调用模型、不自动重放有副作用工具。换工具/工作区开明确分支并保留旧历史。
- LC-T04/05：上传未完成、空交付、缺失/不允许文件、超预算、符号链接逃逸、资源版本变化、资料中的伪标签/控制指令；明确拒绝且不偷偷发不完整上下文。代码脏基线保留，同目录第二写入者拒绝或隔离。
- LC-T05/08：评论锚点绑定精确版本，源文件后改/删除不影响提交版本；部分上传失败不创建可接受版本；提交/评审结算中断可幂等恢复，当前轮次冲突有可理解错误。
- LC-T06/07：跨账号/空间/设备/会话越权，个人专家使用与团队发布，私人资源依赖未授权；拒绝结果不泄漏内容/路径，截图日志/argv/环境/渲染器公开 DTO 不含凭据。
- LC-T06 的 M+ 负例：只有 DSH owner cookie、删去成员 cookie、成员 cookie 过期/撤销/伪造，以及登出后保留 DSH cookie，所有产品账号/空间读写均为未登录且无内容泄漏；不能靠客户端隐藏入口。身份、执行、旧 exact 工作台 API 和未来会话/文件入口须采用同一服务端解析与空间门禁；用真实浏览器 cookie 路径验证 `/zhuma-id` 登录确实覆盖执行入口，普通 RPC 不得静默落回 owner。进程内 createPeer 仅为契约模拟。

## 3. 集成与端到端测试、UI 与正常入口

同数据、视口、主题、交互状态成对截图：1440×900、1280×800、1920×1080，另查 1024px、200% 缩放、键盘/非颜色状态。覆盖长中文、8–12 并行节点、20+参与者及空/加载/错误/禁用/选中/焦点/浏览/编辑；菜单贴触发器、窗边避让、列表高度受控、弹窗滚动与焦点完整。状态/负责人/参与者排版有清楚层级，不堆同权按钮或多条工具栏。

浅/深/系统偏好复用官方单一主题入口，主题切换保持草稿、选中、画布和会话，不调用模型。实际桌面拖窗以坐标变化证明；系统配色转换、聚焦/重开/全屏还原、安装包分别记录，旧的菜单/中性侧栏修复不认证未测拖窗和系统切换。

## 4. 性能、迁移与清理

同机同构建/数据/缓存条件，记录冷/热工作区会话打开、流式首片到渲染 p50/p95、RSS/CPU/句柄/订阅和进程数。方案预算为待验证目标；至少重复 20 次打开/关闭/断流/恢复，未使用工具新增进程为 0，同次执行仅一个对应会话，取消或正常退出后无孤儿进程/监听器。历史与产物保留。

LC-T02/03/06：旧 `dsh` 标识/记录可读；新版本字段、损坏/较新格式有稳定错误；显式演示数据迁移校验来源/身份/内容，重复/部分/中断可重试，回滚后旧数据仍能读取。不得以删除所有历史完成清理。测试只清理本项目隔离数据，保留脱敏报告；不触碰用户日用窗口/工作区。

1. 领域/响应 fixture 证明契约；假网关的真实 DSH 子进程证明对应进程/协议范围；均不认证真实模型质量、多人身份、成品 UI 或安装包。
2. `pnpm check`、正式工作台构建及 CI 按实际 head 执行；PR10 的 211 通过/4 跳过是作者对 `31add8c`/`82bbeee` 的报告，只限对应代码范围，不认证后续 head。`d840ee4` 独立复验为 220 通过/4 真实模型跳过，关闭三处旧集成期待失败，不关闭完整 WP03 评审或 Host 验收；跳过不写通过。付费模型不作为纯领域/协议切片自动新增的门槛，真实业务宣传和相应阶段验收仍需对应真实证据。
3. 首联合 Preview 必过 Zhuma 加一种外部 CLI 的 LC-T02–06/11 正式正常入口；六工具完成前每个已宣传可用的工具都通过 LC-T01–05/11，未完成的清楚列出；完整范围不得因先做两种而删减。
4. UI PR 正文嵌入脱敏可访问的前后图，注明基线/实现 SHA、尺寸、模拟/真实环境及状态；截图与实现不一致更新后复核。

## 6. 安全与隐私测试

LC-T04/06/07 的所有越权、文件逃逸、私人专家发布和资料伪指令必须同时覆盖 API/Host 与实际 UI；来自浏览器的 actor、member、space 伪造不能授权成功。工具凭据只交其受控执行进程，普通日志、错误、遥测、命令行参数、公开 DTO 和 PR 证据都不带值。导入只预检和持久化允许的定义，脚本/插件和任意上传 YAML 不运行。
