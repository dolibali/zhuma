# 联动交付实施计划与四方分工

依据：[方案](design.md)；[验收编号](test-plan.md)。状态：实施顺序已明确，全部目标退出条件仍待各阶段证据。当前源码和 PR10 的差异见方案基线表。

## 1. 交付原则

优先完整路径；每阶段保持独立可审 PR，基于最新已集成 develop。各方保护在途修改，在独立 worktree/topic 分支提交，不直接争写共享 develop。协调审查实际 diff、head/base/CI 后决定可集成部分，不以新增后续范围追溯否定已完成纯契约切片。

六工具都是产品范围，首个联合切片不要求全部同时完成。真实会话链和评审不能仅以更多模拟测试关闭。独立演示的上下文、执行与恢复逻辑可复用；正式入口复用当前 DSH Host、持久化和 React 工作台。

首个可用版现以**本地 Zhuma**为运行主线：可信成员从正常入口创建项目／任务，AI 规划或手工编辑并明确确认，再进入原生工作会话，提交文字／文件，经评审后交下游。码道 CLI 和个人专家后置，原两工具交接及完整专家退出条件继续保留，不作为本次首版前置。24 小时是冲刺目标，不是通过证据；身份、固定产物、幂等、恢复和必要质量不因时间目标降低。当前派工和阻塞只维护在 [#25](https://github.com/dolibali/zhuma/issues/25) 及各工作项，不在本文件另抄进度表。

B 的文件 [#33](https://github.com/dolibali/zhuma/issues/33)、C 的原生会话 [#35](https://github.com/dolibali/zhuma/issues/35)、D 的成员编排 [#104](https://github.com/dolibali/zhuma/issues/104) 并行；A 按有权目录→成员命令／确认→显式规划逐口接入，原生会话／文件口按实际就绪顺序穿插集成。不等待整项后端关闭，也不按候选 DTO 预先实现。

## 3. 跨阶段契约与职责

- A：单写全部 Client、共享 token/CSS/主题/导航/公共控件、plugin 注册、公共 Host／运输装配、`index`／package exports、脚本／发行补丁／CI 及共同文档；覆盖账本／roadmap 的单一维护者。个人专家保留职责但不占用本次核心主线。
- B：单写既有 identity／directory、execution-service／plugin、delivery-draft、提交／评审／文件业务及其 DTO、可信授权和阶段事实；不并改 C／D 独占模块。此前接入证据保留历史归属。
- C：单写新增 `native-work-session*` 模块及对应测试，提供原生 session 绑定、公开事件／流、多轮、停止回执和重开恢复；复用 DSH 原生运行与记录，不另造聊天库、Agent Loop 或默认 factory。既有 B 执行文件需改时给出最小接缝，由 B 处理。
- D：单写新增 `member-workbench*` 服务／HTTP／DTO／测试，及 `workbench-service.ts` 的成员相关必要有界方法；复用既有工作台和 planning 事实，提供显式空间的有权目录、创建／编辑／确认及真实规划。可信身份／目录仍由 B 提供，正常 UI 与公共装配仍由 A 负责。
- 本方案包由协调者本批整理，后续 A 统合索引；B 在自己的契约 PR 对齐实际接口，避免同时编辑共享文件。引用改动给出具体接口/版本/受影响调用，不凭字段名称认定兼容。
- B／C／D 逐口提交业务模块、准确 DTO／操作事件矩阵、DI／注册／导出需求、实现 SHA 与证据，由 A 做 Client 与公共入口集成。公共模型或其他跨域文件变更先报协调划界；任何共享文件转交在 PR 明确当前写者和接续 SHA。
- [Agent能力对照/新增行为](design.md#agent-能力对照与证据边界2026-10-25)与[专项验收](test-plan.md#agent-专项场景2026-10-25增补待执行)为现有阶段的追加门槛。B 先核对原生/外部工具真实能力，冻结具体请求/结果/事件、授权/代次/预算/取消/持久化/迁移；A 才接正常输入/队列/定向协作与真实状态。接缝或纵向证明失败停止该能力扩展，保留人工路径和历史；当前顺序只读 #25/#35，不在这里复制实时阶段或并行新开运行框架。

## 4. 开发与 PR 交付

双方 UI 开发前读方案中的 diagram-design README/SKILL 与现有 `ui-design.md`，使用 frontend-design 校准真实页面。PR 描述包括采用机制、用户路径、契约变化、实际 CI、截图及未覆盖边界；后续外观/交互改动更新图片。纯后端声明无 UI 变更。

仓库提交前 `pnpm check`；上游基线变化才按既有规则更新锁定并 `pnpm upstream:check`；正式工作台构建和浏览器 CI 按现有 workflow 执行。每个缺陷补针对性回归，不能依赖私有状态或吞失败。真实模型四项跳过不能写通过，当前无付费调用授权。

协调每轮只跟进新 head/实质回复/到期承诺。B-M1a 草稿出现前集中 PR10；出现后 M1a 进度迁到该 PR，PR10 只跟踪 WP03。避免在旧 PR3 和每个 A PR 重复派工。评论已送达与已确认接单分开；有实现交付即更新旧通信判断。

## 5. 迁移与发布顺序

每阶段交付含代码 SHA、依赖 base、启动/种子命令、作者证据、独立验证及限制。head/base 变化只复核受影响部分；合并绑定审过的 head，遵守有效 rulesets。文档合入只确认范围和分工，不能关闭 LC 功能验收。

新入口 Preview 可停用，默认 DSH 驱动始终可用；未知格式/未授权演示数据保留只读，兼容迁移先校验再提交、可重试，源不删。完成条件为验收清单相应编号在对应版本/平台有实际证据，包含恢复/权限负例，且无已知阻塞缺陷。

## 6. 延期工作

复杂运行重排/嵌套执行、高级统计趋势与外部平台按现有 FR10/11/14 独立批次；码道与个人专家后置，六工具及完整专家范围保留。SSO、自助注册、计费、微服务/HA 不进入当前范围。首个切片不导入这些尚未实现服务；接口不可用显示明确缺项，不用占位成功。

## 7. 完成标准

每阶段按实施表退出，不以作者测试数判断。本次首个可用版须两独立身份从正式成员入口完成创建／规划／确认、本地 Zhuma 同一工作会话的真实多轮／停止／重开、文字／文件固定提交、全员评审及下游读取，并有越权、重复和失败／恢复证据；人工编辑／提交不依赖模型。两工具同会话交接仍按后续 LC-11 专项验收，不因本地闭环通过而关闭。A／B／C／D 同步已验收 SHA、待审 head 和未覆盖范围，覆盖账本以最终代码／证据更新；协调继续推进尚未完成阶段，未验证能力不宣称可用。
