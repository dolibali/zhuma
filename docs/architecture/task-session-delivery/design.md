# 任务、工作区会话与交付评审联动方案

状态：用户确认的范围与实施方案，2026-10-22；2026-10-23 按 B 的接入证据修订。实现、接口冻结及验收分别记录。配套：[实施与分工](development-plan.md)、[验收清单](test-plan.md)。本方案补充 [架构边界](../../architecture.md)、[FR01–17 覆盖账本](../../product-coverage.md) 和 [WP00](../../contracts/wp00-execution-delivery.md)，不将已有局部交付升级为完整 FR 验收。FR16 身份空间、FR17 测试部署是覆盖账本新增编号，不在原需求 V1.0 的 FR01–15 中。

## 1. 决策摘要与用户结果

统一路径：创建目标并规划或复用工作流 → 确认分工 → 我的工作项 → 选择专家、执行工具和运行位置 → 本地 workspace 会话 → 连续交互 → 固定版本产物 → 多人评审、退回重提 → 下游工作项与项目成果。

专家决定职责和方法，执行工具决定运行方式，workspace 决定文件位置，产品空间决定资料权限。四者独立。人工使用 Agent 后，原交付责任保持不变。任务入口与 workspace 列表打开同一个会话，消息、停止、授权和产物状态同源。

首个联合切片先贯通可信身份、人工交付与评审，再接 Zhuma 和一种外部工具的完整会话链；六种工具全部保留在范围内。复杂嵌套执行、批量反馈、高级效能趋势随既有 roadmap 分批，均不是首个切片的隐性依赖。待办、模板复用、空间登录和资产导入的原有要求继续有效。

用户于 2026-10-22（America/New_York）进一步确认：同一工作会话内可以显式切换 CLI，通过可查看的上下文交接继续工作，并进入同一任务的产物评审。新增 LC-11 / LC-T11，细化 LC-02–06；先完成 Zhuma 加一种外部 CLI 的纵向证明，再扩展其余工具，不将六套适配同时作为首批前置。

## 4. 数据与控制流

执行区提供“专家（可选）／执行工具／运行位置”，Zhuma 为本地 DSH 的产品名称；保留旧 `dsh` 数据标识的兼容映射。Zhuma 优先复用当前 Host 的原生会话与已打开工作区。外部工具复用原生会话协议；Codex app-server、Claude SDK、OpenCode ACP、码道 JSON/指定 session 是接入候选，均按实际版本验证。Zhanlu CLI 的独立协议尚待核实；参考产品内嵌后端不认证独立 CLI 能力。

确认开始后先持久记录关联，再登记 workspace 会话并启动执行；任何失败保留可恢复记录。每节点独立工作会话，标题带任务/节点，标注执行工具并提供返回任务。工作会话是用户持续处理同一工作项的入口，原生执行段分别引用 DSH 会话、provider 原生会话及 Run 尝试；各 ID 从服务回读。连续对话路由到当前段；失败重试建立新尝试，退回修改后显式重提才开新评审轮次，切换 CLI 新建可追溯段，不覆盖旧原生 ID。任务入口与 workspace 入口仍落在同一工作会话页面，不能要求重建任务或手动拼接历史。只读历史不激活模型；关闭视图不等于停止运行。

会话沿用 DSH 聊天布局与公共组件，显示工具实际提供的公开流、提问和授权。运行中补充区分排队/已接收/已生效；不支持实时注入时排到下一轮并说明。两处发送经过同一 Host 幂等命令，停止直到真实回执才确认。进程断开显示中断；重开先补历史和事件缺口，再由人显式继续。不得伪造原生 DSH 模型请求、推理内容、工具事件或用量。

开始前上下文摘要可展开：任务目标/验收、用户补充、精确专家/Skill/MCP 版本、授权项目资料、前驱已接受版本与交接说明。内容按数据处理并定界；资源内容不可改写控制策略。缺必需内容或权限时阻塞并定位原因。数据在执行 Host 按权限物化，不能把他人/服务器绝对路径直接当本机文件。保护当前工作区脏改动；同目录并发写采用明确互斥或隔离 worktree，不自动 reset/stash/删分支。

产物分代码变更、正文文档和文件。代码显示执行前基线、真实 diff 与已运行的验证；文档/文件有安全预览。提交冻结内容、校验和、来源 Run 与版本；评论绑定准确内容位置与轮次。退回保留需修改义务；新提交开新轮，全员通过才接受并给下游。之后聊天或改本地文件不改变已评审版本。项目只索引同一 ArtifactVersion，不复制第二套业务事实。

本地专家视图支持搜索/分类/收藏/导入/详情/使用，内置可复制修改、升级保留个人变更。团队专家与本地专家复用稳定定义，不绑定单一 CLI。个人直接使用无需先建团队任务。团队任务使用私有专家默认在本人设备执行；他人/后台要复用时，显式发布脱敏团队版本并重新授权依赖。默认迁入研发相关候选先核对定义、依赖和许可；候选 UI/UX、文件化规划、Mermaid、研发文档，其他专家按实际清单确认。公开工程不包含内部提示词、私人路径、记忆与凭据。

项目四入口：概览聚焦目标、待处理/阻塞、里程碑和最近交付；工作提供同源列表/看板/工作流；资料与成果按任务/节点/类型/负责人筛选并侧边预览，关联版本、评审与来源；成员管理人和专家分工，连接/设置按需展开。固定参考和当次运行快照分开；项目 AI 使用允许且明确选择的资料。

### 同一工作会话内交接 CLI（LC-11，已确认、待实现验证）

用户看到稳定的任务/工作会话与连续时间线，底层允许多个明确归属的原生执行段。首例为 Zhuma 在当前 Host 的已打开 workspace 工作，交接到一种已资格验证的外部 CLI，再提交同一任务的产物；回到 Zhuma 时按其真实能力恢复原会话或创建带交接来源的新段。段只保存关联和执行配置，不新建聊天内容库、Host 或 AgentLoop；消息历史仍由 DSH 标准登记/存储承接。实际多段展示和原生驱动接缝在 S2 小范围证明后冻结，不能拿外部终端或镜像日志代替正常入口。

交接遵循以下规则：

1. **预览不执行。** “专家／执行工具／模型／运行位置”独立；选择目标 CLI 时检查安装、版本、登录、能力、设备与 workspace 权限，显示实际支持的操作。产生交接清单不调用模型、不启动目标进程。模型切换仅在该 CLI 支持的下一轮生效，不能承诺任意工具都热切换，也不能改写其他工作项的全局 CLI 配置。
2. **在可核实的边界交接。** 空闲时提供“切换工具继续”；活跃时提供“停止并交接”，先拿到源段真实停止回执。停止被拒、超时或断开未核实时，不启动目标写执行。节点本来不可执行时不能借交接绕过依赖、评审或需修改门禁；允许的只读准备与执行权限分开。
3. **保留源与唯一当前段。** 每次确认携带源工作会话/当前段版本、Run 世代、目标工具实例和 workspace、清单版本及幂等键；同键同内容重放，异内容冲突。同一工作区写权在源段释放后才转交目标；并发切换只有一次可接受。目标真实受理后才更新当前段，后续输入/停止/授权只送当前段。旧段迟到事件保留归属，不覆盖当前状态。目标不可用或启动失败保留源历史、交接回执与错误，不能伪造成功或自动回放源段工具。
4. **上下文可核对。** 冻结清单记录任务/节点目标与验收、用户补充、已确认结论、当前代码基线/真实 diff、文字与文件快照、已运行验证及结果、待办问题和未解决评审意见。前驱已接受产物、当前候选草稿和历史聊天明确区分；引用包含来源、精确版本或校验和、权限及预算。用户可预览并选择交接范围，目标实际收到的内容与确认清单一致；内容变化使旧清单失效，缺项/超预算明确阻塞，不静默截断或补造成功。
5. **重新授权而非复制权限。** 目标工具、专家依赖、空间/任务、设备和文件重新检查。仅交接允许的公开消息和资料；不迁移凭据、隐藏推理、未决工具调用或原生授权回执，不重放执行命令。外部工具需要的新授权由真实用户另行处理。交接记录与内容只在相同授权边界可读，不自动上传私人完整会话。
6. **中断可对账。** 在停止、冻结、目标登记、启动或受理前后刷新/崩溃，均从持久关联与回执核实，不自动重复 spawn。状态未知显示待核实；已停止的源段不显示仍运行，尚未受理的目标不显示已执行。关闭未确认预览只丢弃选择；取消页面等待不撤销已确认交接，换回源工具须发起新的交接并重新校验版本。
7. **评审继续约束任务。** 交接不更换任务负责人，不替代节点执行命令，不自动接受草稿、推进下游或改变当前评审轮次。新段可读取有权的退回意见；原执行者修改后显式提交新版本/新轮，全部评审人通过后才接受。提交冻结代码、正文和文件的真实内容、校验和及采用的来源 Run/段；后续任一段聊天、文件修改或工具切换不改变已评审版本。

界面沿用 DSH 聊天与共享组件：同页“对话／改动／产物”，执行过程按需展开；时间线显示“从 Zhuma 交接到目标 CLI”、当前工具/模型、交接阶段和清单入口。侧栏/任务深链维持工作会话位置，历史段可读但不会误将输入发给旧 CLI。重开恢复当前段、选中位置与未提交草稿，不自动继续执行；无效关联有明确回退。A 单写导航/共享控件/注册，B 自负交接业务页面、会话驱动、上下文与评审前后端。

参考 [CC Switch 会话管理](https://github.com/farion1231/cc-switch/blob/07265bc97035a51db7d4ce58890ea3c3e66076cc/docs/user-manual/zh/3-extensions/3.4-sessions.md) 与 [路由说明](https://github.com/farion1231/cc-switch/blob/07265bc97035a51db7d4ce58890ea3c3e66076cc/docs/user-manual/zh/4-proxy/4.2-routing.md)，快照 `07265bc`：采用按项目组织、能力提示、结构化历史/改动和按需读取；其恢复入口调用原 CLI 终端命令，路由切换主要改变后续请求的模型供应商，历史分块读取不等于实时 Agent 流。没有据此认证跨 CLI 原生会话迁移；本产品采用显式交接，不引入通用代理、全局配置接管或第二套会话库。

### 身份选择与正式入口挂接（2026-10-23 决定，待实现验证）

B 的 `b/id0a-identity` / `docs/contracts/b-id0a-identity.md` 已用发布的 Connection 包复核：浏览器共享 `browserPeer` owner，exact `/api/zhuma/*` 不提供产品成员身份；`createPeer` 可以在进程内承接服务端确定的成员。其 `identity-session.ts:488–513`（owner 回退在 `506–512`） 在没有成员 cookie 时退回 owner。作者已指出：删除成员 cookie 后可读到 owner 所属团队资料。该行为不符合 LC-T06，不能通过“要求用户一直登录”的操作约定补救。

采用 B 的 M+ 方向：复用 DSH webServer、credentials、Peer、remote-access 和 storage-domain，由 B 实现最小产品成员会话。等待上游多身份（U）可作后续替换，但不作为当前多人切片的前置；单 owner 映射（M）仅保留隔离的本地单人场景。代价是 B 维护有界的会话签发/撤销/过期与版本，不能复刻整个 DSH 认证或将 owner API 暴露给团队。

- 产品多人模式必须持有效成员会话。缺失、删除、伪造、过期、撤销的成员 cookie 均返回未登录，不退回 DSH owner；owner 的本机控制能力不自动授予产品账号或空间权限。
- 会话由服务端凭据校验后确定 account，成员 Peer 只由可信服务创建。策略允许不能替代每次资源/空间授权；同源/Host 防护也不能代替身份。正文、查询串和请求头中的 actor/member 都不决定操作者。
- B 单一维护认证解析与执行入口的连接：当前 cookie `Path=/zhuma-id` 不会覆盖 `/zhuma-exec`，普通 RPC 又会落到 owner，因此不能把两者原样相接就声称多人已通。B 提交覆盖所有产品请求/事件的统一认证适配及路由/cookie 范围；A 只挂载，不在 UI 或 plugin 再实现一份身份逻辑。
- 旧 exact 工作台读写入口在多人暴露前也须受相同产品会话/空间门禁，或保持只能由隔离的本机 owner 访问；不能留下绕过登录读取全局工作台的旁路。当前单份 global 不直接成为跨空间数据源。
- 账号种子通过显式导入验证器、只在空库写入；不提交固定口令或真实凭据。先单实例测试，复用 DSH 持久化；TLS 监听/可信代理下 Secure cookie 的处理随测试入口一起验证，不宣称当前 HTTP 探针已适合对外部署。

A 维护已打开的工作台域、Host 组合/构建入口与客户端注册，B 不重复打开同名 domain。A 提供供 Host 内部使用的 `readWorkbench` 接缝，并挂载 B 的 identity/execution 模块和 InboxPanel/提交/评审入口。读取接缝不能直接向浏览器导出全量 Workbench：B 在服务边界完成可信账号、空间及任务授权，A 消费有权投影。具体签名/加载顺序由 B 在 S1 映射中给出，A 确认后单写共享文件。当前 `b/m1-2-service` 的 owner/进程内 Peer 接法只认证契约模拟。

## 6. 行为接口与失败规则

以下是待映射到既有命令/Remote 的行为契约，不要求新增同名 RPC。按阶段冻结：S1 只要求 B 先交可信身份与 IF-03 中人工提交/评审/读取/待办的实际 DTO、协议版本及实现位置；IF-01 的会话操作和 IF-02 随 S2 原生会话 PoC 前交付，不阻塞独立的 M1 领域/服务开发。IF-04 的导入/发布 DTO 由 A 维护，B 提供资源授权与运行能力接口。未完成对应映射时该边界仍待冻结，不得宣称架构实现通过。

## 7. 恢复、迁移、观测与验证门槛

复用现有 Run、ArtifactVersion 和 DSH storage；兼容 `dsh` 标识和旧记录版本，新字段显式版本化。PR10 演示数据仅在格式校验、授权、来源与校验和可核对后显式导入；未知身份/权限记录只读保留，不默认提升为团队真实数据。迁移重复/中断可恢复，保留源；回滚关闭新入口并继续读旧数据，不删除唯一会话/产物。任务完成不自动清理历史，清理生命周期须与用户可追溯性相容。

### 安全、隐私、权限与遥测

记录脱敏 request/Run/会话关联、版本、接收/停止阶段、错误类别与耗时，足够定位断流/重复请求；不记录原始提示、原始输出、凭据或文件正文。公开证据使用虚构业务数据。当前执行者由可信 Host 会话确定，来源资料不能通过声明 actor/space 自我授权；工作区会话入口与任务入口执行相同校验。远程团队后台不能直接调用户机器 owner API，必须经过设备归属授权。

### 质量属性场景

| 属性   | 环境、刺激与响应                          | 度量与门槛                                                 |
| ------ | ----------------------------------------- | ---------------------------------------------------------- |
| 一致性 | 两入口同时发送/停止同一工作项             | 幂等请求仅一条，顺序一致，当前 Run/轮次不被旧结果替换      |
| 恢复   | 活跃执行时 renderer/CLI/Host 中断再打开   | 历史可重建、缺口可定位；无重复副作用、无伪造完成；显式继续 |
| 可用性 | 工具缺认证、设备离线、依赖未连            | 开始前明确不可用，未产生模型调用，已存草稿可继续编辑       |
| 权限   | 非成员从任务或 workspace 会话访问同一文件 | 两处均拒绝且不返回私人内容/路径                            |
| 性能   | 同机100条历史/20次视图切换与流式          | 按本节性能预算测量，新增未使用 CLI 进程为0，订阅不增长     |

### 性能、稳定性与可运维性

桥接层复用原生事件序列与持久化，按序合并临时流并让最终记录结算。单订阅缓冲建议上限 1MiB，达到阈值暂停生产或从持久日志补齐；无法背压的供应商要显式断开并标记缺口，不能无界堆积。具体上线值与实际协议预算在 S0/Poc 冻结，性能表是待测目标。Host 持有进程与句柄，停用适配/正常退出释放；renderer 仅持观察订阅。崩溃后先核实原进程和原生会话，再决定恢复，绝不由 UI 自动重试有副作用操作。

### 风险、证明与架构冻结

首个 PoC 必须证明：正式工作台启动 → 当前 workspace 原生可见 → 真流式 → 同 CLI 第二轮 → 停止回执 → 重开可追溯 → 同工作会话交接一个外部 CLI 并继续 → 固定产物和评审。公开接口不足时先提交最小补丁面、兼容/回滚与默认 DSH 回归；禁止先横向做六套页面。若必须另建 Host/业务库或无法满足会话控制，停止扩展并重议接缝。付费模型真实验收仍须用户另行授权，本次恢复协调不改变该边界。

## 8. UI 参考与降低模板感

A/B 开发 UI 前阅读 [diagram-design README](https://github.com/cathrynlavery/diagram-design/blob/7a12007b5a4246894f342a2e52e78facbc62eca3/README.md) 与 [SKILL.md](https://github.com/cathrynlavery/diagram-design/blob/7a12007b5a4246894f342a2e52e78facbc62eca3/skills/diagram-design/SKILL.md)。参考快照 `7a12007b`，用于设计校准，不安装或执行第三方脚本。采用语义层级、克制焦点、删减无信息元素、关系连线清晰、实际尺寸检查；每个 PR 简述“参考机制→操作问题→采用/调整理由”。

参考主要面向静态图解。其默认珊瑚色、字体、零阴影和节点数量预算不是本产品规范；沿用中性浅深主题、已认可的适度圆角/微弱阴影、单一区域一个主动作。业务图保留所有节点和真实依赖，可折叠分层但不丢语义。布局通过留白、对齐和表面表达层级；角色和状态可辨，长中文/连线不遮挡，默认可读，明确全图适应和当前位置。

PR 正文实际界面前后图必须同数据/视口/主题/交互状态，注明基线与实现 SHA；公共样式含浅深，控件含展开态，必要时录屏。真实 Host、视觉交互、浏览器 fixture、模型和安装包分别标注。截图存在或 CI 成功不等于视觉认可。

## 10. 验收定义

需求 LC-01–11 对应 LC-T01–11；首个共同切片通过 S1/S2 及 Zhuma 加一种外部 CLI 的 LC-T11，才可称任务—工作会话—CLI 交接—产物评审接通。全部工具/个人专家/项目视图按各自记录逐批验收，安装包/多平台/测试部署独立。文档与契约通过不等同功能通过。冻结必须同时有实际 DTO 操作映射、逐边界错误/幂等/预算审阅和纵向证明；映射缺项或已知权限/并发/持久化阻塞缺陷会阻止依赖阶段。新增源证据、固定上游接口失败或实测预算失败才重开架构选择。
