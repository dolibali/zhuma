# 成员文件交付界面

范围为 [#33](https://github.com/dolibali/zhuma/issues/33) 的正常 Client；服务、字节与授权事实见 [文件后端](b-m1b-files.md)。实时交付版本及验收结论仍留在 Issue／PR。

## 上传与提交

交付表单支持多文件选择和拖放，每项交付最多 20 个文件，单个最多 20 MiB。队列顺序上传；准备、上传校验、失败与取消等待分别展示，进度不伪造百分比。失败与取消保留原 File 和请求键，显式重试使用相同字节与幂等键；取消不声称撤回已持久化的上传。

Client 对真实 File 字节计算 SHA256，通过精确 `upload-file` 字节端口提交，校验回执的文件名、大小、媒体类型、上传 ID、摘要和空间策略。只有完整有效回执才加入表单。上传队列仍有项目时，保存、恢复和提交暂停；载体保有期间参与现有离开守卫。API／节点／版本／轮次变化取消旧载体，迟到回执不能加入新表单。

草稿保存完整引用和显示名称。已完成文件不再被一律视为未上传；正文、链接或非空已上传文件任一存在即可提交，只有零字节文件不当作有效交付。未完成的旧引用仍可保存、查看和明确移除，不能改旗标冒充上传。冲突恢复保留本地新上传和明确移除的墓碑，不静默清空远端文件；合并后超出 20 个时须先移除多余项。

## 固定版本读取

`FileReferences` 先读授权元数据，显式预览或下载才读取完整字节。按用途分别提供准确定位：草稿为 `draft`；评审为固定 artifactVersionId 与 roundId 的 `review`；退回对照为原 artifactVersionId 的 `artifact`；下游为准确 sourceNodeId 和固定 artifactVersionId 的 `upstream`。不改为最新版本，不从上传者或文件摘要推导权限。

每次操作使用当前成员／空间预检，并核对响应完整用途、节点、版本、上传 ID、长度和 SHA256，消费前后检查取消与当前代次。客户端预检不替代 Host 对象授权。文件操作共用 65 秒等待上限；普通 RPC 保持原上限，含文件的固定提交使用文件等待窗口。桌面 cookie 桥只增加准确 `upload-file` / `file` 路径。

只有服务明确返回可内联的纯文本才展示，使用转义的 `pre`；本地同时复核 UTF-8 和危险字节边界。预览最多显示前 128 KiB，并提示可下载全文；文件完整性始终先对全部返回字节校验。其他格式提供下载，不把 ID 拼成公开文件 URL。下载 Blob URL 在超时或卸载时释放；原始错误、凭据和存储路径不进入页面。

## 验证边界

字节／回执／取消的 Node 测试使用显式运输与权限 double，只认证契约。React/HappyDOM 验证多文件与纯文件提交、同键重试、轮次切换拒绝迟到回执，以及评审／历史／下游用途绑定，不认证真实权限或浏览器布局。

`member-file-client-host.test.mjs` 从公开 `@zhuma/client` 入口生成当前 API 证明字节，在独立真实 Host 子进程中经过真正 Cookie、身份、JSON 域和附件实现验证上传、草稿恢复、评审预览、退回重提、下游固定内容及越权拒绝。计划由可信测试种子预置，不冒充成员创建或 AI 规划。正式 `test:host` 同时绑定 emitted Host 摘要与 Client 文件证明；正常桌面 GUI、真实模型、Agent 自动提交及安装版仍分别验收。
