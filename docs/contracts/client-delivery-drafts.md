# 交付草稿客户端

对应 [#32](https://github.com/dolibali/zhuma/issues/32)，消费已合 [#82](https://github.com/dolibali/zhuma/pull/82)／[#83](https://github.com/dolibali/zhuma/pull/83) 草稿服务。实时交付与验收结论保留在 Issue／PR，本文件只记录接口、交互和证明边界。

## 协议与版本

`readDeliveryDraft` 在既有 `draft` 路由只发送 taskId／planId／revision／nodeId。`saveDeliveryDraft` 在同一路由附加独立草稿 expectedVersion、幂等键以及正文、全部链接和文件引用。不附加 spaceId、账号或轮次字段，不导入 Host、不新增客户端授权事实。成员 HTTP API 沿用每次新鲜会话预检和当前空间／代次门禁。

读取值必须完整包含 version、text、links 和 files。版本为非负安全整数；文件必须有完整元信息且 uploadComplete 为 false。缺失、异常、读取失败都不能变成版本 0 或空草稿。保存成功回执必须为请求草稿版本的下一版，不能用节点执行版本替代。真实 DTO 的双向类型检查留在 conformance 测试。

草稿版本跨轮次递增；提交后的空墓碑仍有真实版本。提交成功只失效当前 Client 草稿基线，不在本地把版本重置为 0；新轮次重新读取后消费墓碑版本。幂等键按操作类型、完整目标、expectedVersion 和全部内容生成指纹；同一请求失败后重试复用键，内容、文件元信息或版本基线改变时换键。服务冲突和幂等错误原样保留，不假装保存成功。

## 保存与恢复

原提交／退回修改入口都使用同一编辑器。页面打开只发送草稿读取，不自动保存草稿、提交或启动执行。服务查询可能补偿既有下游解锁缺口，不承诺整个执行域零写。初始读成功前可以编辑，但保存与提交关闭；读取只恢复尚未编辑的字段，已经编辑的文字／链接保持不动。读到有内容的草稿而用户已编辑时，提供对照选择；空草稿不制造无内容的恢复提示。

“保存草稿”是明确动作。状态只根据实际读写回执和当前输入显示：尚未读取、尚未保存、有未保存修改、正在保存、已保存及草稿为空。所有链接都保留，不只取第一条；草稿可保存未写完的链接，提交仍按原 HTTP(S) 规则校验。保存和提交共用一条操作通道，同一上下文内读取、保存、提交不能并发抢写，写入时暂锁输入。上游 blocking 只影响提交，不阻止保存草稿。

发生草稿版本冲突时保留表单并关闭写入；“查看已存草稿”只读取对照，不立即覆盖。“恢复到表单”明确采用远端内容；“保留当前输入”保留本人的修改，同时采用远端未修改字段和未明确移除的文件引用，再使用读回的版本作为下一次保存基线。“取消恢复”不覆盖输入，也不解除尚未解决的冲突。草稿冲突与提交的 Node.version 冲突分开处理。

## 文件引用

首批文字／链接切片不实现上传、文件正文预览或下载；正常文件 Client 接续见[成员文件交付界面](client-files.md)。已完成回执、纯文件交付与固定读取按该接续契约处理。读取到的全部文件元信息保留用于保存，界面只展示 ID、类型、大小和未上传状态，校验和与策略标识不进入展示。单项“移除引用”是可恢复的表单修改，明确保存或提交前不写服务。

文件未上传时提交关闭，提示移除引用后可提交文字／链接；保存仍完整携带引用。不会静默把非空 files 改成空数组，也不把 uploadComplete 伪造成 true。服务 `files-not-accepted` 仍是错误，不解释为成功。冲突恢复时只沿用明确移除的对应引用，远端新增引用和其他未改元信息保留。

## 生命周期与证明

完整节点身份／API 变化沿用现有表单 key；节点版本、状态和当前轮次形成独立异步边界。同节点更新保留当前编辑输入，但读写回执须与正在呈现的上下文和当前操作匹配。切换、卸载、登录／空间失效或新轮次使旧读取、保存、提交的 success／catch／finally 全部失去回填权。成功提交立即关闭本地草稿边界，直到待办／轮次更新后重新读服务；不允许旧保存或读取再填回已提交表单。Abort 是运输与展示取消，不承诺撤销已到服务的写入；服务仍负责权威版本和跨轮墓碑。

旧 [#68](https://github.com/dolibali/zhuma/pull/68) 冻结 `916aba91dc6726171ab26bd053f842183b582209` 只作明确保存／恢复方向参考，不整支合旧表单、单文件编辑器或 Host，不继承初始猜 0、截断链接、读后覆盖输入或缺少代次保护。使用 frontend-design 与 [diagram-design 固定参考](https://github.com/cathrynlavery/diagram-design/tree/7a12007b) 的语义层级与删减原则；沿用中性浅深 token、公共控件和紧凑状态，恢复对照只展示真实返回内容，文件引用不冒充文件产物。

Node 测试覆盖协议、字段完整性、独立版本、文件标志、HTTP 成员／空间与迟到拒绝。浏览器响应重放覆盖正常入口、读取前编辑、明确保存、失败重试／换键、冲突恢复／取消、文件保留／移除、上游阻塞不阻止保存、新轮墓碑和旧身份／轮次回执。旧浏览器执行类重放补充真实空草稿 DTO 和读取就绪前置，原浏览器产品断言保留；SSR 初始快照按新增首读门禁更新，不用 SSR 证明读取完成后的提交可用。专用草稿重放记录全部读写。编译 harness、响应重放或 SSR 不认证真实存储／授权／文件字节／Native；额外浏览器、同数据前后图和必要实服务由协调侧安排，A 不运行浏览器。没有本地草稿库、自动保存、Agent 或后续范围扩展。
