## 交互与请求路径

“我的工作”通过成员会话验证后并列读取待开始计划与执行待办。
计划选择器只展示服务返回的 taskId／planId／revision／title；读取、重读、鼠标或键盘选择都不会开始执行。
选定计划后复用原 `StartPlanPanel`，只有明确点击或键盘激活“开始执行”才调用 `start-plan`。
请求携带精确的不可变计划引用及幂等标识，B 在这一时刻重新授权。
正式成员入口通过 [空间边界](member-spaces-client.md) 绑定所选 spaceId；查询必须核对成员／空间回显，开始携带同一空间约束。旧未绑定 API 调用仅供兼容，正式页面不使用它回退全空间查询。
客户端不从 owner snapshot 找计划、不推导权限，也不自行把节点标为执行中。

开始成功后清除当前选择，重新读取权威目录，并触发执行待办重读。
待办重读保留同一工作项正在编辑的输入，沿用已有提交／评审上下文隔离修复。
目录加载或失败时不能新提交开始；目录移除所选版本时清掉该选择，不默选另一个版本。
同名计划按精确引用保留独立值，只有显示名称冲突时补任务／计划标识帮助区分。
未知网络结果重试复用相同请求标识；切换目标或新会话采用独立表单生命周期。

## 会话与异步隔离

`ExecutionApi.startable` 是有类型的只读方法，发送空请求体，校验成员及计划引用字段、整数版本和重复引用。
Client／S1 类型快照双向检查实际 DTO。API 不把客户端 actor 放进请求体。

成员 HTTP API 将目录和待办返回的 actorId 与当前认证账号比较；不一致先使当前会话失效，不显示另一个账号的数据。
每个 API／成员生命周期隔离目录查询和开始命令；任务／计划／修订选择使用完整引用和选择令牌。
目录重读取消旧读取并核对请求代次；旧成功、业务失败、异常或 finally 不能清掉新选择、错误或 pending 状态。
开始请求的取消只停止当前 UI 等待和接受回执，不承诺撤销已经送达 Host 的操作；实际状态以权威重读为准。
服务根据当前请求的成员 Cookie 重新授权，客户端显示一致性检查不替代服务器授权。

## 验证入口

定向 Node 契约覆盖 typed 目录、异常／重复引用、精确请求体、账号变化、取消，以及静态渲染不读取／不执行。
既有执行客户端回归继续保留，现有成员入口测试允许新增只读 startable，并继续禁止隐式开始及 owner 回退。

协调者可运行既有 `node packages/client/tests/browser/server.mjs`：

- `http://127.0.0.1:8796/?startable-plans&strict`：独立计划区，默认四个虚构计划，包含任务、计划和修订差异。
- 加 `&formal`：直接渲染正式 `MemberExecutionPage`，复用原生 Fetch／成员边界，重放同一接口；可查看开始后目录与待办刷新，以及已有交付输入的保留。
- 上方会话切换按钮供契约诊断。测试控制器可挂起读取／开始，故意忽略 AbortSignal 后返回旧结果以检验 UI 自身门禁。

自动交互在 `startable-plans.spec.mjs`，沿用仓库 Playwright 配置与浅深主题。
场景覆盖发现／重读／选择不执行、明确开始及连点、键盘、成功重读、当前交付草稿保留、未知结果重试、重新授权拒绝、
任务／计划／修订切换的旧 success／failure／reject、会话切换、乱序目录、账号不一致。

这些 HTTP／RPC 响应重放不是生产授权或真实模型执行证明。A 不操作浏览器；新 UI 浅深图及正文证据由协调者提供。
PR 正文更新保留“协调界面证据”段。空间选择／切换由 #31 的独立边界承接，不在本模块复制；完整工作树／文件库或其他保留工作项另行处理，
不把当前可开始计划入口表述为整个 #32／FR16 已验收。
