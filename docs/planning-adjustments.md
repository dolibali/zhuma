## 操作与范围

已有任务打开 AI 规划后，明确选择调整范围。自然语言要求不被当作授权范围，也不推断“其余不变”就足够保护配置。

| 范围             | 允许改动                                                    | 保持原样                                                              |
| ---------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| 整个任务         | 现有完整工作流协议，允许重新编排                            | 用户的任务负责人、参与范围及其他任务字段不由模型改写                  |
| 仅当前节点执行者 | 执行者、对应分工依据                                        | 该节点的评审、资源、输入／交付及其他字段；所有其他节点与结构          |
| 仅当前节点配置   | 名称、说明、执行者、评审、Skills／MCP、输入、交付、分工依据 | 其他节点全部字段，以及工作流名称／层级、节点 ID／顺序、依赖和画布位置 |

局部模式不支持增删节点、拆子流程或改依赖；需要这些操作时明确选整个任务。原先的整个任务入口保持可用，不改成隐含局部范围。

结果先预览，不自动保存。第一轮对比已保存草稿；连续调整对比上一份尚未应用的草案，展示节点新增／修改／删除及重要字段的前后值。层级、依赖、顺序和位置变化也可见。可定位节点、查看删除前内容及切换调整前／规划结果；查看调整前时不能误触继续规划或应用。

只有“应用草案”才保存完整待应用草案。与已保存工作流相同的结果不能重复应用；仍有阻碍问题时不能应用。已有人工修改先经原有保存链成为规划基线；失败、取消及迟到响应保留上一份草案。这里没有新增任务阶段或运行中热应用。

冲突后成功读取最新版本时，旧提案、调整前预览标记及比较基线一起重置到新任务；仍保留有效的节点选择和调整范围，能够继续局部规划。取消读取或读取失败则保留原提案、比较基线和视图。恢复修复 `2af0c35` 的定向结果另见[记录](review/planning-adjustments/recovery-proof.json)，不覆盖首批截图来源。

## 服务端契约

`PlanRequest` 仅新增可选 `adjustment: { nodeId, fields }`。fields 是已知可编辑配置字段的非空、去重列表；不允许依赖、位置或未知字段。WorkbenchApi 只发送目标与字段范围，不上传由浏览器自称权威的基线图。

Host 继续用 `expectedRevision`、`baseProposalId` 校验任务和版本，从已保存任务或持久化审计中的未应用提案捕获基线。未知节点在模型调用和审计写入前拒绝。模型结果仍先经过完整结构／引用校验，再由领域比较器检查所有非授权字段；包括同一目标节点中未授权的评审、资源和交付。越界进入既有一次修复，仍失败就拒绝，不静默裁掉有依赖影响的更改。局部问题回复也必须保留基线图，不能以空图取代已有草案。

沿用原有版本冲突、取消、审计和幂等。相同请求重复返回同一提案；复用请求 ID 改范围拒绝。规划不会写任务，应用仍走带收据的持久化命令；新建的调整范围不授予人员、工具或文件权限。

工作台和提案持久化 schema 不变，新字段只在规划请求与审计字符串输入中使用。Host 和 Client 应一同更新；旧 Host 的严格请求 schema 会拒绝新的局部请求，不静默退回整个任务。原来的整个任务请求不带 adjustment，保持兼容。公共导出只新增领域比较／范围类型与校验，不新增 Host 服务。
