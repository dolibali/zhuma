# 团队工作操作台：A-UX1

## v1.3 工作会话窗口

使用者在节点“使用 Agent”中查看目标、配置、消息与输入。沿用中性浅深 token（浅色纸面 `#ffffff`、正文 `#252a30`、辅助 `#66717c`、分隔 `#e3e6e9`；深色纸面 `#1b1d21`、正文 `#e6e8ec`），系统字体与原公共控件；标题 16px、正文 14px、辅助 12px。参考 frontend-design 的内容优先与 diagram-design 的语义层级／删冗余，解决窗口外框、内部固定 740px 和左右 padding 重复挤压的问题，不引入新皮肤或装饰卡片。

窗口仅保留一层最大 1120px 的边界，窄窗预留两侧 16px；内部标题、说明、配置、消息、输入使用同一宽度和内边距。原消息滚动、底部输入、配置展开、关闭回焦与脏输入守卫保持。空态仅限制段落行长，不将整块重新居中限宽。长目标以折叠“工作说明”展示完整原文和换行，局部滚动；这项 display-only 内容不进入执行定位请求，不删掉已输入或已保存的内容。

源码／SSR 契约只核完整文字、默认折叠和被动查看不执行。正常桌面的长短目标、展开配置／说明、连续消息、发送／关闭回焦、浅深主题及缩放由协调在同一候选检查，并保留前后及展开态图片；本文不作为视觉通过证明。

本文件保存共同产品原则、交互约定、设计来源及证据边界；实时交付状态以工作项为准。A 维护本文件、公共主题和交互组件；B 的待办、产物与评审页面复用同一套组件，不并行改写公共 CSS。功能测试与视觉/业务验收分开。

## A/B 共同产品与交互准则

以下是实现和自查必须采用的完整适用原则，来源与任务边界见 [共同执行说明](https://github.com/dolibali/zhuma/issues/25#issuecomment-6393807114)。阅读链接、登记技能或通过编译，都不等于把原则落实到了可操作界面。

1. **从操作任务出发。** 动手前明确谁在什么场景要完成哪一步。负责人、执行者和评审人应能在工作页认出当前空间、当前工作和下一步。账号、产品空间、项目、任务、设备 workspace 与执行工具是不同概念，不能混进一个选择器。空间切换只进入另一个有权空间，不是刷新数据、创建账号或启动执行。
2. **结构表达真实含义。** 标题、分隔线、分组、卡片与图标必须表达层级或状态；删除重复标题、同权工具栏、套叠卡片和无信息增益的说明。浏览态优先正文，配置按需展开；渐进展开不能隐藏主要入口。简化不删任务路径、正文、当前轮次或真实依赖。
3. **入口可发现，动作有主次。** 承担切换的名称或图标提供可点击线索、可访问名称及键盘焦点。一个区域只突出当前主动作，刷新和详情降低视觉权重，危险操作与常用操作区分。换色、圆角和阴影不能代替交互修复。
4. **风格服务工作。** 沿用下文中性灰白/石墨灰、宿主中文系统字体、品牌原稿和语义 token；用字号、字重、对齐、间距、表面与微弱阴影建立层级。主按钮中性高对比，蓝色用于少量链接/焦点，绿色用于成功。frontend-design 的有意选择、真实内容、自我批评和克制装饰适用，营销 hero、额外展示字体或强行视觉实验不适用。diagram-design 的语义、单一焦点与删除冗余适用，默认珊瑚色、字体、零阴影及 9 节点/12 连线预算不覆盖现有产品主题和真实业务图。
5. **文案和状态共同构成交互。** 使用用户认识的对象与动词，同一动作全程同名，不暴露实现术语。加载保持尺寸与输入；hover、pressed、focus、disabled 分别可识别，不以整块透明度表达禁用。空态解释范围并提供实际可用动作，失败给出真实原因和恢复方式；未采集、无权限、空结果与加载不可混为“没有”。不展示未实现的创建、加入、上传等虚假操作。
6. **菜单真正可用。** 复用共享控件，锚定触发器、默认下方、窗口边缘避让、限制高度并允许滚动；长中文仍可辨识。支持 Tab、方向键、Enter、Escape 和合理焦点归还，选中项有勾选，不只靠颜色。空间少时直接扫描，超过 8 项沿用 SingleSelect 搜索，无结果有明确提示。新增公共能力由 A 单写，B 提供参数和场景，不另建主题、浮层或控件库。
7. **展示与可信事实一致。** 空间目录与选中事实来自现有可信服务；页面选择不授予权限。顶部和账号菜单共享一个成员/空间 controller；保留脏输入取消/确认、切换中状态、旧响应与回执隔离、撤销立即收口。打开、搜索、刷新和切换不触发模型或执行。已读不消工作义务，正常运行不冒充待处理，评论不冒充通过，文件元信息不冒充文件字节，不以假数据填补缺失权限或状态。
8. **研究落到取舍。** 说明参考机制解决哪个操作问题、采用什么、舍弃什么，绑定具体实现与验证。官方资料研究不能称为竞品登录实测；不照搬品牌、侧栏、账号体系或本产品尚未接通的操作。
9. **实现前先定方案。** 简述场景、主动作、信息层级、布局/控件选择及舍弃项；实现后自查。空间入口的具体方案见“工作页的空间切换”；B 的业务页复用这些准则，不并行修改 A 的公共文件或重做服务。替代方案要说明操作依据，不能静默削减用户要求。
10. **证据按层交付。** 实质交付给出“参考机制 → 操作问题 → 实现文件 → 证据及边界”。截图使用同数据、视口、主题和状态，绑定实现 SHA，提供前后与展开态并嵌入 PR；用户附件和私有路径不公开。源码、契约、实际 HTTP/持久化、GUI、模型及发行证据分别记录。A/B 不操作浏览器，额外视觉/行为验证由协调安排；契约通过不等于真实 Host、系统主题、原生缩放或安装验收。

## 全应用巡检与分批验收

以上原则适用于整个应用，不能只检查空间切换或静态截图。按[全应用巡检约定](https://github.com/dolibali/zhuma/issues/25#issuecomment-6393871015)，协调者负责从正常入口亲自操作、复现问题并在修复后验收；作者报告、CI 和单元/契约测试作为辅助证据，资料研究不能代替真实体验。实时发现、优先级与阶段只记录在原工作项，本文件保存方法与责任，不另建进度表。

本产品首版面向**桌面工作台**。主要布局与交互验收视口为 1440×900、1280×800 和 1920×1080；1024px 桌面窄窗口与 200% 桌面缩放用于检查正文滚动、弹层避让、键盘可达和核心操作是否仍可完成。实际桌面 Host 与浏览器视口证据分别记录。360px 手机尺寸不属于首版必过范围，也不构成移动端适配承诺；不得仅因该压力视口失败而阻断桌面切片、增设手机专项样式或删减桌面导航及专家等业务能力。真实桌面窗口或缩放若暴露操作问题，按影响和实现版本有界修复。

先建立完整页面、正常入口和用户路径清单，逐项区分已实现、部分接入与缺失入口。未实现功能明确登记，不能用模拟页面冒充交付，也不静默删减原 FR/LC 范围。巡检按以下操作链分批覆盖：

1. 登录、账号、空间切换与导航。
2. 创建目标、AI 规划、工作流复用、手工编辑、分工与工作树定位。
3. 待办、开始工作、草稿、提交、评论、退回重提、双评审与下游解锁。
4. 项目、成员、专家、资产导入、资料与成果。
5. 持续会话、工具交接与统计。
6. 设置、浅深主题、响应布局与原生桌面。

每条问题必须绑定完整实现 SHA，并记录实际环境、账号角色和数据状态、复现步骤、预期与实际、操作影响、脱敏截图或交互证据、优先级、单一主责、关联工作项和明确退出条件。布局问题说明它造成的层级、查找、点击或阅读障碍，不能只记录“不够好看”。缺失入口或未验证能力也必须保留可追踪结论。

优先修复阻断工作、误导状态、丢失输入和难以发现的核心操作，再处理信息密度、层级和重复控件；纯修饰不挤占人工协作主链。A/B 各保持一个主切片，发现清单不表示同时开工或全站重写。A 维护 Client 公共入口、导航、共享样式/控件与 Host 装配；B 提供业务事实、DTO 和服务，其业务 UI 复用共同设计。交点先明确主责，再按既有工作项增量交付，不重开已限定关闭的身份/Host 事项。

每批合入前由协调在同一实现版本实际点击和键盘操作，检查浅深主题、展开态、错误与恢复、长数据和受影响布局；功能链从正常入口走完，不能直接调用内部方法跳过界面。合入后仍须建立目标版本与证据的对应关系。未覆盖内容明确留待验收，CI 通过不等于产品验收；付费模型、文件字节、原生安装等原有授权和验证边界保持，单人定义管理模式的 UI 检查不能证明团队授权。作者交接可操作入口、数据准备方法、版本和剩余边界，协调提供实际操作结论。

## Agent 工作会话：补充、队列与协作（设计要求，待真实接缝）

依据[能力对照与源码边界](architecture/task-session-delivery/design.md#agent-能力对照与证据边界2026-10-25)和[#35](https://github.com/dolibali/zhuma/issues/35)。场景是负责人在长任务中补充要求、查看实际处理阶段，以及多个Agent围绕具体工作项协作。采用Codex的当前运行/下一轮区别与Claude的定向独立上下文；不复制其品牌或恢复独立讨论模块。A单写Client、公共控件、导航/导出及必要Host运输，B提供可信能力/目标/消息/回执DTO；无真实接缝时不展示假成功操作。

- **输入与主动作。** 当前工作会话底部输入框在运行中可编辑，邻近显示目标节点/会话与当前运行；支持时主动作“补充当前任务”，下拉渐进提供“下一轮处理”。不支持实时补充时明确显示“下一轮处理”及能力原因，不能沿用即时文案。停止独立于发送，不靠停止重启模拟插话；打开、刷新、切换目标不执行。
- **队列与回执。** 队列紧邻输入框，可展开查看目标/顺序并编辑、撤回、调整尚未送达项；已受理记录保留，后续修改以关联补充表达。只展示协议能证明的本地排队、Host受理、运行端收到、待采用、已采用/拒绝/失败阶段；“已收到”不能写成“已完成”。断线或回执丢失显示待核实，提供准确查询/恢复，不自动重复发送。当前轮结束竞态保留输入并明确选择下一轮，不能误投新Run。
- **会话间协作。** 从当前节点/会话内选择具体有权协作者，意图为提问、补充、请求检查或共享固定引用；目标、可信来源、来源节点、reply-to与实际送达结果可辨。点击回复回到原问题/工作项，等待回复时独立工作可继续，依赖阻塞仍明确等待。Agent消息标为另一Agent来源，不能变成人的授权/评审票；不广播全部历史、不再造聊天窗口层级。
- **资料与产物。** 初始展示有权固定输入清单的名称/来源/版本/类型大小/有界说明，按需展开实际读取范围和来源；没有摘要不造摘要。上传完成、引用装配、实际读到、固定提交、评审通过、下游解锁各有准确状态。全Agent节点同样显示依赖/串并行/汇聚与等待原因，配置人工评审时等待真人，Agent评审显示真实独立评审身份和本轮版本。
- **克制与可恢复。** 沿用既定中性浅深token、系统字体、图标与32/36px控件。正文/输入优先，来源与技术定位按需展开；用对齐、留白、表面和少量状态强调层级，不堆同权按钮/冗余说明。长中文、队列和消息局部滚动，键盘可选目标/展开/撤回并返回合理焦点。切账号/空间/节点遵守脏输入守卫和迟到响应隔离，不能把另一个会话的回执显示到当前目标。

延续frontend-design的单一主动作与自我校验，以及已指定[diagram-design参考](architecture/task-session-delivery/design.md#8-ui-参考与降低模板感)的语义层级、克制焦点与删冗余；使用本文件桌面尺寸/200%缩放/浅深标准。实际操作门槛见[Agent专项验收](architecture/task-session-delivery/test-plan.md#agent-专项场景2026-10-25增补待执行)，由协调正常入口亲测；本文无可见UI实现或截图通过结论。

## 工作页的空间切换

执行者与评审人在“我的工作”中从一个有权空间转到另一个空间。空间名称是主要入口；刷新只是重新确认当前空间，放在名称旁的 32px 辅助图标中，保留“刷新空间”可访问名称与 tooltip。正文账号信息仍只在侧栏底部显示。

布局为紧凑的一行：`[当前空间名称 ▾] [刷新图标]`，下方为工作内容。名称使用现有 13px、600 字重，4px 控件间距与中性 hover/边界，键盘焦点复用公共 token。触发器宽度随内容收缩，上限 320px，并为刷新预留宽度；长名截断但 tooltip 保留完整名称与个人/团队类型。展开项显示完整名称、类型与当前勾选；浮层的长名换行、有限高度、搜索、滚动和碰撞避让复用 SingleSelect，不再新增选择器。

## 使用目标与结构

成员模式保留两个真实侧栏入口：“团队工作台”管理当前有权空间的项目与任务，“我的工作”处理待开始计划、交付和评审。两者复用唯一成员会话与空间控制器，正文不再重复主导航。切换只改变展示代次，不开始任务或规划。个人专家仍按独立范围后置，成员入口不回落 owner 数据。

离开成员表单统一使用现有紧凑确认 Modal，取消和 ESC 回到发起控件并保留输入；确认后才卸载旧页。在途保存/规划和未应用草案同样受保护，已发送写入仍可能完成；旧页迟到结果不能继续导航。官方布局的配套 `registerPanelGuard(target, proceed, signal)` 在所有 `selectPanel`（含 Conversation 的 null）提交前运行，后续导航、守卫卸载和布局关闭使旧 continuation 失效，且提交前再查目标注册。未补丁运行时明确拒绝装配成员入口；旧单人退出语义保持原行为。源码/布局单元与响应重放测试分列，实际侧栏、新会话/工作区导航、焦点和浅深主题由协调亲测。

账号入口采用宿主侧栏底部的真实 footer action，展开显示头像／账号／当前空间摘要，窄栏显示可识别头像和辅助名称；账号弹层只分组已接通的身份、空间选择和退出，设置与主题继续使用相邻官方入口。桌面整列隐藏不等于56px窄栏，账号随列隐藏并通过宿主展开控件恢复。插件生命周期拥有唯一成员会话与派生空间选择，正文不再重复顶栏账号。具体接口、脏输入守卫、设计来源及验收边界见[空间与侧栏契约](contracts/member-spaces-client.md)。

面向需要把团队目标落实为人与专家分工的负责人、执行者和评审人。任务详情只回答三件事：正在处理哪项工作、它位于哪里、下一步能做什么。识别点是“目标路径 + 当前工作节点”，不是装饰性指标卡。

采用紧凑页头 → 单一工作流工具栏 → 主工作区与可收起属性栏。标题和状态常驻，长需求按需展开。初始画布定位当前节点，保留可读缩放；“适应全图”是明确的全局观察操作。确认后的浏览态显示可读属性；编辑态使用分组控件；AI 提案在主区预览，关键问题和应用动作在侧栏。

人员选择使用同一可搜索目录：短姓名与人/专家身份优先，职责与能力作为详情。创建任务、管理参与者、选择执行者和多位评审人复用它。引用仍由领域校验，界面不能凭选择结果授予工具或业务权限。

复用官方 `ctx.theme` 的 `system / light / dark`，默认与持久化均由官方 ui-theme 管理。工作台外观入口调用同一服务；不写独立 localStorage、不监听另一份系统主题，也不重挂载编辑器。官方 ui-layout 将主题投影到 `body[data-ds-dark-theme]`，公共 `--zm-*` 变量据此变化。应用启动的主题预加载仍由官方负责。

公共入口：`@zhuma/client/workbench/ui` 导出 `Button / Appearance / Modal / Field / MemberPicker / ParticipantSelect / MultiSelect / ExpandableText`。`Appearance` 只订阅官方偏好，其余组件统一操作等级、表单、选择和可访问名称。字段错误贴近操作，版本冲突保留当前修改并提供显式读取最新版本。小屏将属性栏降级为可关闭抽屉，不压缩画布文字来塞下所有内容。

## 操作等级与状态

主、次、轻量、危险四种按钮共用一组样式定义；32px 控件、7px 圆角、13px 中等字重、轻边界与极轻阴影。浅深模式分别定义正常、hover、pressed、focus、loading、disabled。禁用使用独立中性背景/文字/边界，不用整块 opacity；清除原生 appearance，避免宿主或浏览器的原生填充。加载通过 `Button busy / busyLabel` 保持控件宽度和 `aria-busy`，不增加跳动或浮起效果；减少动态模式停止转动。

生成前，“生成工作流草案”是侧栏主操作；生成后，“应用草案”是唯一主操作，“重新规划”为次级，“放弃草案”为轻量。应用与放弃在同一行动行，避免满宽实心按钮堆叠。不可用操作通过邻近状态或 title 解释原因。蓝色填充的旧版完整页面作为对照，本轮选择中性主方案，不增加缺少用途差异的第二套品牌色按钮。

## B 页面接入

B 在独立文件实现执行服务与产物、评审组件，通过公开 DTO 和 `WorkbenchApi` 的后续扩展读取状态；A 负责 `plugin.tsx`、页面注册、包导出与共享 CSS 的合并。包内组件按 `.js` 相对引用公共控件；跨包仅使用上述公开入口。工作台根使用 `.zhuma`，原生对话框使用 `.zm-dialog`，主题样式由插件一次加载，禁止组件重复注入或另存主题偏好。

执行入口必须从 `AppliedPlan` 的冻结定义取得节点 ID 和资源版本；UI 不从下拉框生成可信 actor，不自行推进执行状态。产物正文、图片与文件预览保留原始配色，不加反色滤镜。B 可以提出所需控件参数，由 A 统一补充，避免创建第二套按钮、人员目录或主题系统。

## A-UX1b 实现

本批集中三种界面，单独提交，不阻塞 B-M1。任务清单将导航与筛选并列，紧凑显示数量、项目、真人负责人及完整参与人数；减少同等权重的横线，保留表格对齐。详情页将项目路径与返回放在一处，状态/负责人/参与者在标题下相邻，保存与确认保持固定位置。

画布与属性栏使用两块轻边界表面，而不是层层嵌套卡片；节点、连线、定位和缩放含义不变。AI 规划区把草案放在可滚动正文中，补充要求与下一步动作固定在底部；规划依据按需展开。重规划失败或取消保留上一份提案，等待替换时不可应用/放弃；用户主动取消只显示中性状态。小屏属性栏覆盖整个工作区，避免矮窗口的标题挤占草案与操作空间。共享控件 API 保持兼容。

借鉴 Linear 对导航/内容的权重区分与 Geist 对表面层次的最小化原则；本次没有修改官方 SidebarRoot 或另写导航壳。固定上游的侧栏插件拥有 New Session 与 Workspace 区域，未暴露按工作台页面隐藏这些入口的配置；宿主导航的进一步产品裁剪仍需独立、可验证的集成，不能用模糊 CSS 选择器隐藏真实功能。

参考 [ChatGPT 插件 UI 指南](https://developers.openai.com/plugins/concepts/ui-guidelines) 的单一主动作、就地修改、渐进展开及复杂编辑使用充分空间；不把嵌入式卡片限制直接套在独立工作台。Apple Materials 的内容/控制层次与 Grok 的输入聚焦是后续比较方向；目前未验证 Grok 登录后企业功能，Apple 页面正文在当前网页读取工具中未取得，不作为已验证实现证据。不会通过毛玻璃、高饱和渐变或发光来掩盖信息层次问题。

## A-UX2a：目录与编辑

项目、成员和资产使用可筛选的行式目录，主操作保持在页头。项目显示背景和任务数，成员显示身份、职责、能力和可参与状态，资产显示类型、用途和启用状态。长中文说明保留两行，完整内容在编辑中查看；不把资产正文铺满目录。成员可按真人或专家筛选，资产按类型筛选，搜索无结果时直接清除筛选。空目录提供对应创建入口。

新建和编辑复用一套表单：名称和类型并列，正文滚动，取消与保存固定在底部。错误留在当前弹窗内，失败保留草稿；保存时禁止重复操作和关闭。嵌套人员选择器按 Escape 只取消当前选择器，不关闭外层任务表单。导入定义使用键盘可达的按钮，读取失败就地提示，同一文件可以重新选择。这里导入的是能力定义，不代表安装或授权 MCP。

超过六项的能力选择增加搜索，列表在局部滚动，筛选不清空已选项。项目、人员、资产与任务配置继续复用既有公开组件，没有改变组件签名、持久化契约或官方主题入口。

版本冲突的恢复入口保留在任务工具栏，独立于可关闭的错误提示。读取最新版本先确认会放弃的内容；取消确认保留草案，读取成功后恢复持久化版本。规划连续调整的上下文契约保持不变。

同数据、同视口的浅深对照及验证边界见 [A-UX2a 证据](review/ux2a/README.md)。本批不包括执行待办、交付评审、多用户身份或安装版桌面验收。

## A-UX2b：完整工作树导航

全树中选择节点只改变定位，进入局部工作流使用“进入本层工作流”或“打开子工作流”；面包屑与“上一级”保留视图模式，恢复每层最近选择。相同任务版本中，定位不改变草稿、保存状态或调用模型。读取新版本后原节点失效时回退到最近仍可见的上级；索引和文案不保留不可见对象的名称。

复用现有右栏切换配置和层级导航。层级可搜索、折叠，搜索结果显示所属路径，搜索输入本身不改变画布选择。选择隐藏分支中的搜索结果会展开它；当前定位的祖先保持展开。直接前置/后续节点可以点击定位。画布高亮当前位置、祖先及相关边，实线表示同层依赖，虚线表示逐级拆分；定位保留 100% 字号，全图概览仍由用户主动缩放。节点增加上下间距，避免全树中包含工作流名的卡片相互遮挡。

沿用 [React Flow 的键盘可访问性机制](https://reactflow.dev/learn/advanced-use/accessibility)：Tab 到节点、Enter/Space 选择，通过受控选择变化同步右栏；右栏层级使用原生可聚焦按钮和展开状态。小屏复用现有抽屉，关闭和进入本层后焦点返回触发入口。没有增加第二套树引擎或执行状态模型。

[同场景证据与验证边界](review/ux2b/README.md)。当前仅支持同任务的层级编排，不能等同于公司级跨任务权限和嵌套执行闭环。

## A-ENTRY：目标创建与规划衔接

创建任务先写目标，其次选择项目和参与者；默认“AI 规划”，也可“使用工作流”或“从空白开始”。名称可由目标首行生成，负责人可稍后补选但确认前必需。参与者使用同一可搜索目录，触发按钮显示少量姓名与总数。没有另加附件、规则或解释区；结构化模板已接入搜索／图预览／映射，旧文字必须显式转换，不能只有入口。

创建只在用户提交处理器中启动一次规划，保存完成后的组件仅订阅该请求。规划失败在同一任务提供“重试规划 / 手动编排”；取消、离开和迟到响应有明确处理。生成结果按原有流程预览、应用、自由修改、保存及确认，打开和刷新不会隐式重新生成或执行。

负责人信息栏明确覆盖通用表单的纵向布局，标签与触发器同行，长姓名有边界、小屏整组换行；只读与空值保持同一行高。单选菜单展开定位/字号属于另一个问题，将由 A-UI-controls 验证实际桌面后统一修复，本批不把原生菜单关闭状态当作已解决。

参考机制、完整视口浅深对照与代码/浏览器/真实 Host 证据边界见 [A-ENTRY](review/entry/README.md)。自动规划的资源选择、分工质量与局部修改保护按 A-PLANQ 单独验收，不能通过入口简化推断已完成。

## A-TEMPLATE 与共享业务接入

模板在独立目录内浏览真实图、角色与资源，选定后只在创建表单显示摘要和本次映射。预览首次按真实弹窗尺寸适配全图，图与工具栏分开；后续缩放不被抢回。清单、工作流和子层级共用真实节点与依赖，无任意数量截断。模板角色仅是定义；任务参与者／负责人仍是真实目录对象。缺项保留明确占位，确认前补齐，人工修改不会因批量映射被重置。

## A-UPSTREAM-CONTENT：从来源按需查看已接受内容

场景：下游负责人提交或修改产物时，先辨认来源与固定版本，再查看需要的正文。复用原来源列表，在visible来源下放一个“查看内容”的原生展开入口，保留details键盘语义，隐藏原生marker并复用空间/账号同一 `ControlIcon` SVG箭头；pending/受限来源保留提示。展开后正文局部滚动，参考链接在其后，文件只有真实元信息；收起清除内容，再开重新读取。来源失败就地重试，交付草稿保持可编辑，不增加重复刷新/保存工具栏或全量正文轮询。

采用frontend-design的任务优先、单一主动作、可恢复失败与克制表面，以及既定diagram参考的语义层级/删除冗余；沿用中性浅深token和系统字体，用间距、版本文字及展开状态组织信息。`UpstreamInputsPanel`/`UpstreamContent`负责来源与阅读，原交付表单继续负责编辑与提交；细节见[客户端契约](contracts/client-upstream-inputs.md#已接受内容按需读取100-接缝)。读取回执须校验成员/空间/完整上下游和版本，文件元信息不冒充预览/下载。源码/DTO/HTTP与SSR、浏览器重放、正常多角色GUI分别验证；本条为实现设计，桌面窗口/200%缩放/浅深/键盘和同数据前后截图由协调安排，不以构建替代验收。
