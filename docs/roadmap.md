# 实施顺序

以 [产品能力覆盖账本](product-coverage.md) 追踪 FR01–17 的实际状态、主责和退出条件。原型主要能力是范围基线，UI/UE 可重做；不能以目录 CRUD、领域契约或布局完善代替用户任务闭环。

## 已有基础与边界

四包依赖、固定官方 DSH、Host/Client 插件、组织目录、计划编排与模型规划提案已建立。A 的组织数据由 Host 持久化；B 的执行/交付/评审状态机和并发契约已有纯逻辑测试。实际执行、我的工作项、人工产物与内容评审尚待 B 的 Host 与页面切片接入。当前不称为完整产品。

成员 B 的执行与上下文演示见 [WP03](contracts/wp03-execution-context.md)。页面默认仍要显式选择执行器。DSH 以子进程运行 `dsh --profile sdk`，自测使用桩，真实网关尚未验收。

A-UX2a 目录/表单及浏览器 CI 已合入；A-UX2b 导航见 PR #6，已合入并完成三层草稿导航验证，不追加装饰性范围。执行状态只有权威服务确认后才展示。

补充当前前置与下一批次：

- **A-UI-controls**：ENTRY 后独立修复原生选择菜单展开定位/字号，统一锚定选择控件。先核对 DSH 公开接口，必要时采用成熟无样式原语；实际 macOS 桌面 100%/125%/200% 缩放、长目录/窗边/弹窗焦点和浅深展开证据单列，不通过 DPR 模拟冒充桌面验证。
- **A-PLANQ / FR02/04/13**：核心优先；复用现有规划器，按候选权限/参与范围、相关性和预算构建依据，保留局部调整中无关人工配置；8 类约束场景与资源对照评估，模型质量和 JSON 合法性分别验收。缺少 B 的权威连接/忙闲事实保持未知，不另建 Agent 循环或向量库。

- **B-ID0 / FR16**：预置账号、真实会话与可信 actor、个人/团队成员授权、空间隔离。先给固定 DSH 的最小适配证据；不把模型平台账号或 browserPeer owner 当产品账号。
- **A-VIEWS / FR05/06**：ENTRY 后接“需要我处理”的具体工作项，以及“我参与的/全部”的列表/阶段看板；同源筛选与计数、下一动作和 B 处理页入口。B 提供任务阶段投影，不从 draft/ready 猜执行；禁止拖卡绕过评审。
- **A-SPACE / FR16**：按 B-ID0 契约实现登录、个人/团队切换和成员入口；树深链与刷新偏好按账号/空间/任务隔离，失效位置回退。
- **B-ID0 + A 集成 / FR17**：本地单实例可启动和重启恢复先行，K8s 为后续指定测试环境目标。演示至少 3 账号/2 团队并有人跨团队；双账号退回重提与第三账号越权拒绝必须真实验证。

下一可用版本必须包含人与 Agent 协作链。A/B 不互相造服务：A 实现组织、规划和共享入口，B 实现可信运行、产物、评审与状态；联合验收从普通任务入口走完整路径。

## 后续与发布门槛

- P1 外部研发平台单独排期；先一个明确需求源/代码平台往返及幂等回写。高级运行调整、复杂锚点和大规模树优化按实际需要拆批。
- P2 再考虑更多平台、外部 MCP 与企业组织治理；不得静默删除已有 P0。
- 桌面继续复用官方实现。独立数据目录、退出/重开、打包/安装验证单列，Web Host 成功不能代替安装版验证。
- 不建设独立 Rules、独立讨论、冗余验收面板和单独多层演示区。保留必要业务审计与版本，但不堆叠解释文案。
