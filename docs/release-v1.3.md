## 固定运行基线

DSH 固定为 `dsh-v0.2.1-rc.4`／`504a01a9578abc2c6f1fb896b1dc322c9fe24f66`，根公开 SDK 依赖使用精确 `0.2.1-rc.4`。上游仍为独立 Workspace／pnpm 工具链；品牌、权限、会话、Skill 隔离及隐私补丁只应用于自有临时构建树，不覆盖用户安装或旧构建树。

原发行补丁在该目标对象上可直接应用，不因升级重写未变逻辑；准备记录同时绑定新 Git pin 与完整 recipe 摘要。`pnpm upstream:check` 核对 gitlink、版本、仓库和干净固定源码；`pnpm check` 与插件／SDK 构建分别验证自有代码和构建兼容性。它们不证明 GUI、真实模型或外部 CLI 已完成业务。

附加社区插件固定为 `@zaimokuza/dsh-acp-adapter@0.2.1-rc.4.1`／源码 `28ccc6745ec82139c684c3642637e93e00d800f2`。构建补丁将它安装进官方 SDK 的 Web Bundle，发行 overlay 注册附加 profile／路由，保留默认 factory 与官方会话、工具、权限展示。新增 Gateway 门禁覆盖插件会话操作；全局会话目录按原生任务绑定逐项过滤，未知结果或注册代次变化拒绝返回，不将任务会话暴露给普通个人会话界面。任务模型选项只读取插件被动缓存，排除需要主动 CLI 探测的路由。

`node scripts/desktop/verify-acp-registration.mjs --sdk <固定且已构建的SDK>` 验证实际发布插件注册、共享 Host peer 图和默认原生 factory；子进程与模型端口是显式禁止调用的契约端口。`verify-session-admission.mjs --sdk <固定SDK>` 验证实际 Gateway dispatch，业务服务为契约夹具。SDK Host／Client／Web 构建不等于正常桌面验收。附加插件的原生工具 handoff 使用固定源码补丁及 pnpm 发布包补丁，详见 [登记](../patches/dsh-acp-adapter/README.md)。只有明确匹配的 Host producer 本代闭包能开启交接，普通配置不能设置执行开关；动态撤销沿原停止与排空路径处理。构建与契约不表示真实 CLI、登录、工作区、工具隔离、停止及业务链路已通过；码道官方认证前置不得绕过。

## 本轮正常入口

- **团队资产与资料**：从“资产”切换资料、工作流、Agent 专家与 Skills。资料使用文件列表和面包屑；可新建文件夹、批量上传到打开窗口时选定的目录、移动文件，点击已发布文件预览，“信息”中维护草稿、来源和固定版本。在线文档保留原入口。目录只浏览元数据，不扫描文件正文；未知大小与草稿修改时间不伪造，日期列仅显示真实发布日期。
- **固定资料与原生 Agent**：项目默认资料和任务草稿共用固定版本选择器；省略引用、明确空选择和具体版本保持原领域语义。创建任务时继承一次，确认计划和 Run 固定原引用；不会因目录移动或新版本发布自动切换。原生 Agent 使用原签名 Run 的按需工具读取，每次仍检查当时权限；列表命中、缓存、会话回复均不等于已读取正文或正式提交。
- **工作流与固定依赖**：已保存任务可“保存为工作流”，到资产中的工作流分类维护草稿并显式发布；从可用发布版本建立独立任务草稿后仍可编辑。专家、Skill 与资料引用固定发布版本，新版本不自动替换既有计划或 Run。正常发布、复制与冷开仍由协调者按准确候选留证。
- **专家／Skill 包**：静态预览后导入草稿，发布 Skill，再为专家明确选择所需固定版本后发布。未满足的依赖不冒充已可用，私有文件不参与导入，导入文本不自动执行。
- **码道与会话**：正常“使用 Agent → 配置 → 配置码道”保存本机命令，并在原运行配置中明确选择执行者、模型与工作区。新工作区首次使用前，先在该目录启动官方码道 CLI，确认目录可信后按提示选择信任并完成登录，再返回开始任务。同一插件经 pnpm 逻辑安装地址或物理地址登记时，按精确同文件核对，避免符号链接路径误拒。保存、打开选项和重开应用不主动启动 CLI；登录、目录信任、真实模型、原生工具、停止排空与正式产物仍分别按准确候选验收。默认原生 Zhuma Agent、工作区与原会话保留，附加 ACP 不接管已有其他执行者会话。

源码、契约、正常桌面、供应商、CLI 与交付结论分别绑定准确实现 SHA；实际证据统一见 [#310](https://github.com/dolibali/zhuma/issues/310)。

## 必要验证

按准确候选补齐可信成员／空间、不可变版本、真实文件摘要、撤权、幂等、停止后的实际排空和冷恢复；历史打开不自动执行。契约测试、真实 Host、正常 GUI、供应商模型与最终安装包分别记录。协调完成正常桌面点击／键盘、浅深与展开态检查；实现者不以源码测试替代该结果。

最终来源须 topic 普通合入 develop，再普通合入 main，经所需 CI 和验收后沿原 Release 流程一次构建。产品根包、四个自有包与桌面构建号统一为 `1.3.0` 后，仍复用现有手动 Desktop Release：默认仅保存构建产物，明确选择发布时才创建新的 `v1.3.0` tag／Release；main 完整 SHA、该 SHA 最新成功 CI、既有 tag／Release 冲突与产物摘要继续由原门禁核对。只认证最终核验的 macOS Apple Silicon（arm64）包；ad-hoc、未公证、无自动更新。Windows、Linux 与 Intel Mac 本轮不作安装／运行通过声明。新版本元数据、PR 或 SDK 构建本身不等于已发布；v1.2 的 tag 和证据保留原范围。
