# 首个 v1.0.0 范围与验收说明

目标产品版本为 `1.0.0`，计划使用 tag `v1.0.0`；根与四个自有 private 包、桌面包版本保持一致。DSH／第三方基线版本保持原样。打 tag、构建验收与正式发布仍由协调者按门禁执行，本变更未发布。

此文记录用户确认的发版边界，尚非已发布公告。实时交付、阻塞和具体证据以 [#25](https://github.com/dolibali/zhuma/issues/25) 与对应 Issue／PR 为准，不另维护阶段表。

## 本轮核心结果

- 正常成员建立账号、项目和任务，选择参与成员／基础专家，通过 AI 规划或手工编排得到可编辑、可确认的计划。
- 分配给人的工作可手工完成，或使用本地 Zhuma 持续会话、模型与 Skill 处理；对话、停止与恢复复用原 Harness。规划确认不自动授予执行或文件权限。
- 文字或文件形成固定提交版本；人工或 Agent 针对该版本评审，退回后按意见修改再提交，通过后下游读取已接受版本。
- 任务和项目消费同源进度与成果；执行、评审、已接受及资源持有分别呈现，未知不伪造完成，取消不算交付。
- 用真实模型与正常成员界面验证核心路径，安装包、启动／重开及数据恢复独立验收。契约、脚本模型与开发 Host 各保留证据边界，不互相代替。

## 后续版本保留范围

非空 MCP 连接、资产／工作流发布版本、批量评论反馈、复杂子流程与工作树执行、效能统计退出本轮关键路径；个人专家直接使用和外部 CLI 继续后置。既有实现、合同、来源、分支和完整退出条件保留，不能以范围后置标为已完成或关闭整个 FR／大 Issue。

## 发行默认与证据边界

全新外部桌面 profile 走首次成员设置；旧 profile 模式与资料不自动迁移。自有代码采用 MIT，第三方版权与许可保留。

产品 Bundle 默认关闭 `session-log-deepseek` 的日志请求附加字段，保留原设置供用户主动选择。旧 profile 的自定义 config 优先级和整体覆盖边界见[发行配置](../distribution/workbench/README.md)。这不代表所有历史 profile 已迁移，也不改变正常任务消息的模型请求。

当前接口、单元测试或组合构建通过仅认证对应版本和层次；真实模型效果、正常界面及安装版结果须有各自实际执行记录后才能确认。
