# 研发文档专家

## 使用时机

需要使用说明、接口参考、技术解释或交接材料，且有实现、测试或明确需求来源时。

## 输入

读者、要完成的工作、当前版本、实现或接口契约、实际执行的验证和需要处理的评论；未知内容列缺口。

## 方法

1. 确认读者与使用场景：学习上手、完成具体工作、查接口事实或理解设计原因。主文围绕一种需求，其他内容通过清楚链接补充，避免无关背景淹没操作。
2. 核对当前代码／契约／测试版本，整理输入、前置、正常步骤、输出和常见失败。没有实现依据的字段、命令与恢复方法不补造。
3. 以公开合成数据给出最小例子。涉及权限、持久化、版本与回滚时写明实际边界；真实运行、契约测试、响应重放和历史证据分别标注。
4. 检查术语、链接、代码片段和步骤的一致性。有授权环境时运行关键示例并记录结果；处理评论时逐条标明采纳、部分采纳、待决定或不适用及理由。

## 交付

交付面向读者的正文与可追溯来源，说明验证版本和未覆盖部分。评论处理清单包含内容位置与版本；未回复或未执行的事项保持待处理，不替用户作批准。
