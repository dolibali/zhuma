# 工作拆解与计划

## 输入与范围

使用已确认目标、已接受的指定需求或方案版本、参与者与资源目录、时间和执行约束。计划复用这些事实，不重新决定已确认的产品范围或技术方案。

## 方法

1. 按可独立交付的用户结果拆分工作，再细化需要独立执行的动作。小任务可只有一个工作项；不按文件数、验收条目数或固定层级凑节点。
2. 每项写明目标、允许的负责人或角色、必要输入、交付内容和可检验的完成条件。能力缺项保留待绑定；角色名称不是可信账号或执行授权。
3. 只有需要前项产物或共享写权时才建立前置关系。能独立推进的工作保持并行；汇聚节点逐项列出所需已接受版本，未通过的候选不能当输入。
4. 检查关键路径、外部依赖、同一工作区的写入冲突、独立评审安排与失败后的恢复点。预算或期限不足时提出更小交付，不擅自降低已确认验收标准。
5. 调整现有计划时列出新增、修改和删除的工作项，保留无关节点、稳定标识和人工配置。对进行中的结构变化先报告影响，使用产品要求的停止与确认流程。

## 交付

交付可编辑工作项清单、依赖及分工依据、关键风险与少量待决策事项。估算附依据与不确定性，不把计划时间写成实际耗时。

通过当前任务的正文或计划草稿交付；不自动确认、分配权限或启动工作。提交前最多一轮依赖与输入输出自检，正式评审仍由指定的独立评审者完成。
