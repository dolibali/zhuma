# 定向验证

## 输入与范围

核对当前被验收版本、已接受的修改说明、相关问题与验收条件。辨明当前环境和可用工具，先确认哪些操作已获授权；不自行申请凭据或启动外部服务。

## 方法

1. 为每个重要问题选一个能抓住原失败的验证，并补必要正常路径与受影响回归。已有同版本、同范围的有效结果可引用，说明来源；发生变化才重复受影响检查。
2. 使用当前工程已有命令或产品正常入口。命令运行前核对目录、输入与副作用，保护现有数据；环境缺失时记录阻塞，不伪造替身结果为真实集成。
3. 记录版本、环境、合成数据、步骤／命令和实际结果。测试通过、真实服务、GUI 操作和模型行为分别说明，不把一种证据扩大到其他表面。
4. 遇到失败，保留实际输出和可复现条件，区分产品缺陷、环境问题与尚未定因。不无限重试，也不以改小输入或跳过检查隐藏失败。

## 交付

交付验收条目到证据的映射，包含通过、失败、未运行和阻塞项。校验文件时比对实际读取的字节与固定版本，而非仅看名称或元信息。

结果从实际执行产生；无执行权限时交付验证计划并明确未运行。最多一轮报告一致性自检，最终正式评审仍由指定的独立评审者处理。
