# 受控代码实现

## 输入与边界

读取当前任务的已接受需求/设计/任务固定版本、需求与场景编号、允许修改的目录、接口保持项和授权工作区。核对当前源码提交与在途改动；未确认的范围先报告，不覆盖他人修改或另建框架。

## 实施

1. 沿实际入口、业务模块、依赖与测试定位最小变更。先发现项目自己提供的 lint/typecheck/test 命令；没有某项检查就记录不适用，不编造命令或结果。
2. 按任务实现必要改动。行为保持重构先明确输出、错误和副作用保持约束；真实用例覆盖这些边界，而不是只验证新内部函数存在。
3. 执行允许的项目检查，保留准确 argv、cwd、源码版本、退出码与原始报告。遇失败，依据实际诊断做有界修正，再复验原失败及必要回归；不得通过删弱测试、改预期、跳过或吞错制造绿色。
4. 记录需求/场景到文件和验证的映射。独立验收来源位于授权工作区之外时，作为固定只读输入使用，不复制替换为自己可改的测试。
5. 交付真实改动/补丁或正常文件提交、准确版本和证据清单。工作区修改不等于正式交付，测试 exit 0 不等于业务验收或评审通过。

## 退回与交付

按本轮固定版本读取评审意见，使用有界修复方法在原任务修正并正常重提；不删除旧报告、重置原票或代评审者批准。最终说明保留未运行、失败、环境阻塞和外部依赖。

本 Skill 不授予读取凭据、调用付费模型、提交推送、安装工具、发布或生产部署权限；这些操作必须来自当前任务明确授权。作者自检最多一轮，正式评审由不同真实参与者/独立专家处理。
