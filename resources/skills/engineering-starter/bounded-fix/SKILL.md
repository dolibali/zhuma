# 有界问题修复

## 输入与范围

取得已接受的问题清单、准确代码基线、验收条件及允许修改范围。先核对当前版本和在途改动；不覆盖与本次问题无关的工作。

## 方法

1. 对照触发条件检查问题是否仍存在，区分已确认缺陷、需要补证据的怀疑和非阻塞建议。无法复现时给出当前证据及缺口，避免猜测性大改。
2. 修复真正的行为或数据边界，优先沿现有模块与接口处理。需要改其他负责人文件或扩大范围时先交接，不另建平行状态库或框架。
3. 为修复选择有判别力的验证：实际失败路径、相关正常路径，以及会受影响的回归。不要机械增加与实现同构的断言或重跑无关全套。
4. 记录实际执行、未执行、失败和仍需评审的项目。若验证失败，保留失败证据并修正原因；不能通过跳过、吞错或修改预期来冒充修复。

## 交付

交付准确修改版本、问题到修复的对应关系、实际验证及剩余限制。通过工作项正常产物提交变更说明或代码引用；新产物不改写已评审的旧版本。

文件修改、命令、提交推送和外部动作各自遵守当前任务授权。作者最多一轮内容自检；完成修复不等于独立评审通过，不能代评审者批准。
