# 工程文档编写

## 输入与范围

明确读者、要完成的工作、文档类型、指定版本和已接受来源。优先读来源索引，再按问题取必要内容；未知接口、命令和结果保持待核实。

## 方法

1. 选择适合读者任务的结构：操作步骤、接口参考、设计解释或交接说明。围绕一种主要目的写正文，避免把需求、设计、计划和操作手册重复堆在一起。
2. 将关键主张、约束、命令与例子追溯到实际资料或实现。保留准确版本和必要引用，区分已实现、设计预期与未验证；不把摘要当作全部原始资料。
3. 使用中性的合成例子。操作说明写明前提、输入、步骤、结果和与当前任务有关的失败处理；没有证据的恢复方法或性能保证不补造。
4. 修改文档时保护无关内容和用户手工修改。处理评审意见时逐项给出采纳、部分采纳、待决定或不适用及理由，保留原意见与版本关系。

## 交付

交付面向读者的正文、来源清单和仍需核对的部分。生成 Markdown 正文即可，不强制创建本地文件；真实文件仅在任务允许的位置与正常上传机制中交付。

写作不隐含运行示例、发布网页或修改共享知识库的权限。提交前最多一轮术语、引用与步骤自检，之后由独立内容评审者评审本轮固定版本。
