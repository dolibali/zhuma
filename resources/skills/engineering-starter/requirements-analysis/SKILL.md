# 需求分析

## 输入与范围

读取当前任务目标、用户已确认约束和有权访问的指定资料。标出来源及版本；没有提供的业务事实、角色权限、性能目标和期限保持未知。短问题直接回答，不强制生成完整文档。

## 方法

1. 用用户操作与结果说明问题：谁在什么场景做什么、现状的损失、成功后可观察的变化。区分用户明确要求、现有事实、分析假设与待确认问题。
2. 按业务结果组织范围，写清输入、输出、主要流程和不包含的行为。保留已确认要求与约束；建议扩展单列，不把设想写成既定需求。
3. 将验收标准写成“前提／动作／可观察结果”。覆盖主要正常流程和与本需求相关的边界、失败或权限场景；没有依据时不编造响应时间、容量或成功率。
4. 检查术语歧义、相互冲突的标准、关键依赖和可行性。可继续的部分先交付；只有确实阻断结论的缺口才提问，合并为最多三个问题。

## 交付

交付需求说明、验收条目与来源对应关系，以及仍需决定的事项。保留原有需求编号；没有编号时可在本次文档内使用临时标识，不冒充服务分配的编号。

在任务允许的产物草稿中交付正文；本 Skill 不读取认证文件、不推导当前账号，也不授予外部写入权限。提交前最多做一轮内容自检，检查范围与验收是否一致；自检不代替独立评审和正式票。
