# 业务测试设计

## 输入与范围

使用指定的已接受需求、验收标准和工作拆解版本；按需读取相关接口或界面事实。明确被测功能、支持环境与可用合成数据。缺少的行为约定列为待确认，不补造实现。

## 方法

1. 建立需求／验收条目到测试点的对应关系，先覆盖核心用户路径。测试对象是产品功能、接口或数据变化，不是用户要求 Agent 生成用例的过程。
2. 针对真实风险选择等价类、边界、失败、权限、重复请求或恢复场景；只在需求相关时采用，不机械要求每种测试类型或固定用例数。
3. 每条用例给出前置条件、数据、操作与逐步预期结果。预期描述可观察行为及必要持久状态；避免“工作正常”等无法判定的文字。
4. 标记优先级及其用户影响。说明用例是拟定、可执行还是被环境阻塞；执行证据只有实际跑过后才能填写。

需要完整用例字段或例子时，按需读取[用例格式](references/case-format.md)。

## 交付

交付可执行用例、覆盖关系和尚无判定依据的缺口。使用合成账号与资料，保留输入的准确版本。生成用例不触发测试平台写入、运行命令或模型调用。

提交前最多一轮覆盖与可执行性自检；独立评审者仍需对本轮固定用例版本提交正式意见。
