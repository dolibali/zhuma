# 独立原生评审接缝

工作项：#35 / #41。仅约束 C 的原生会话接缝；D 决定真实成员控制权、当前轮资格、专家定义与资源授权，并在原节点队列落票。A 单写公共注册、运输与 UI。本批只有数据/描述/一致性检查和兼容测试；没有注册新工具、启动评审 Agent、签发 lease/ref 或写业务评审结果。

## 身份、版本和事实

- `actorId` 始终是实际真人 controller；实际 task/plan/revision/node 保持原值。专家不是伪造的 MemberResolution，review Run 不是作者 Run。
- D 的 `ExecutionReviewBinding` 是目标与专家的唯一定义；目标含准确 round、artifact、artifact fingerprint，principal 含 controller 与冻结 reviewerRef。C context 只包裹该 binding、原九字段定位和显式 review role，不造另一套专家版本 ID。
- 作者 scope 的九字段 strict schema、作者 key 字节、作者绑定 v1/v2、`complete_work@1/@2` getter 及 hash 不变。带 review 的 D scope 不能直接传入旧作者 schema/入口；显式投影原定位只得到数据，不得到授权。
- C 的 v3 review envelope 与 D 的节点 `nativeExecution` v2 是不同记录边界。C 仍使用唯一 `zhuma_native_work_sessions` 域、原 `bindings` 表、原 DSH 会话/日志/Agent factory、owner、队列和排空，不新建聊天库或业务评审库。
- review key 包含 role、原节点 key、完整 D binding；具体原生运行地址再包含 run/generation/segment。作者、不同轮次、产物、配置评审专家或版本不能共享运行身份。
- 公共 JSON、schema 解析、相同 hash、readRef、ACK、SDK idle 或 CLI 成功都不是授权或批准；只有实际 SDK 源链、真实目标读 lease、完成切点和物理排空可供后续 owner 签发 opaque ref。

## 验证边界

`native-work-session-review-*.test.mjs` 是 schema/getter、范围/顺序和兼容契约测试。兼容用例直接执行未改动的作者 parser/Service 与发布版 DSH StorageDomain/JSON 后端，验证 marker-only 和 v3 记录让旧读取器拒绝且既有文件 bytes/mtime 不变；没有运行旧应用二进制。合成页/seq/hash 只证一致性，不能证明模型真的看过内容。

下一阶段必须在原 SDK 中证明作者与独立评审者 session/agent/地址分离、真实 read→result→completion cut、撤权/停止/排空、D 原队列具名落票/丢回包确认，以及新进程恢复。当前不认证这些运行路径，也不认证 UI、成员登录、真实模型质量或安装产品。
