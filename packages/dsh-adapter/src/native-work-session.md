# Native work session seam v1

Scope: #35's first Host-internal native session slice. `openNativeWorkSessions(ctx, options)` opens one `zhuma_native_work_sessions` storage-domain and composes the public DSH 0.2.1-rc.2 AgentRegistry, Agent, session persistence and event services. It does not mount RPC routes, establish a member identity, create an Execution Run, submit an artifact, or replace the Agent factory. The normal member transport and shared exports belong to A; current Run authorization and fixed submission belong to B.

## Authority and composition

B must establish a Run through the existing execution facts on an explicit, idempotent begin. A Client never supplies a new authoritative Run ID. An existing Run produces `NativeWorkGrant`: trusted `actorId/spaceId/taskId/planId/revision/nodeId/runId/generation/segmentId`, an authority-lifetime abort signal, and synchronous `assertCurrent(action)`. The grant is an internal capability, never JSON supplied by a Client or model. It must validate actual member, space, node, Run and segment facts for the requested operation. Missing authorization must reject; no owner fallback exists in this module. Native session IDs and metadata are not capabilities.

Every service operation checks authority; awaited operations and each emitted frame recheck it. Revocation aborts active native work and prevents late frames reaching the caller. UI read/stream cancellation has a separate signal and does not cancel the Agent. The scoped native pre-step, request and tool gates also check current execution authority. A scoped request may not silently switch the provider/model bound to the Run.

`options.compose(agentCtx, binding, grant)` runs in the unpublished native scope. It returns a bounded necessary-task context and the exact allowed tool names; an empty allowlist disables tools. DSH's restriction API accepts inherited/global tools only, so the adapter passes only actual global names to that mask. Scope-owned tools remain registered locally. A monotonic execution guard enforces the complete declared allowlist and current grant; publication and each pre-step also check that the actual scoped tool surface exactly matches it. An unexpected scoped registration fails publication instead of being silently exposed. A supplies authorized goal and fixed-reference metadata and composes resource tools here; skill/MCP/resource authorization is not integrated by this slice. It adds no source body by itself. Composition failure or stale authority rolls native publication back.

## Concrete service operations

All locators below come from the grant. Errors are stable `NativeWorkError.code` values or a caller-owned authorization rejection. A must project these to public errors without exposing arbitrary exception text. No operation logs prompts, credentials, paths or provider errors.

| Operation             | Inputs and result                                                                               | Ordering, limits and failure                                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`                | grant → optional binding + native `idle/running/detached`                                       | Read-only. Does not create/resume/wake; both task/workspace navigation resolve the same full node/account/space key.                                                                                                                                                                                                                                                 |
| `send`                | grant; requestId, text, followup/steer/queue, exact selection/configurationId → message receipt | Per-locator serialized; 200-character IDs, 16,384-character nonempty text, 256 receipt reservations per binding. Persist reservation before native admission, flush before received acknowledgement. Same ID+fingerprint reconciles native facts without resending; changed input fails idempotency-mismatch. Ambiguous admission is unknown, never automatic retry. |
| `queue`               | grant → attached flag + native pending items/id/text/target                                     | Does not resume a cold Agent. Detached metadata cannot imply an empty native queue. Bodies are read from DSH only, not the mapping store.                                                                                                                                                                                                                            |
| `updateQueue/edit`    | grant; pending messageId + bounded text → accepted                                              | Public native replace; absent/already-claimed item fails not-pending. Flush then acknowledge.                                                                                                                                                                                                                                                                        |
| `updateQueue/remove`  | grant; pending messageId → accepted                                                             | Public native removal with durable cancellation fact; cannot retract an already claimed message.                                                                                                                                                                                                                                                                     |
| `updateQueue/reorder` | grant; complete unique next-turn messageId permutation → accepted                               | One native durable splice; cannot move claimed or next-step inputs. Flush then acknowledge.                                                                                                                                                                                                                                                                          |
| `stop`                | grant → stopped/pending                                                                         | Fences sends/queue mutations admitted before this stop, cancels native activity with keepInbox, then waits for idle and session durability. Entire native stop wait is bounded to 5 seconds. Timeout/detached state is pending, never stopped; no execution write right is released by this module. A new explicit send is distinct.                                 |
| `history`             | grant; after=-1, limit=100, optional UI signal → binding + native events                        | Read-only cold-safe persistence handle; flush attached session first; at most 100 events and 262,144 serialized bytes per page. Never replays tools or opens an Agent.                                                                                                                                        |
| `follow`              | grant; after=-1, optional UI signal → scoped event/assistant-stream/status/gap frames           | Subscribe before history; durable seq drops overlap. At most 128 buffered frames/524,288 bytes and 262,144 bytes per frame. Overflow ends with a gap + durable cursor; re-read history. Abort/return removes listeners and buffers. Live chunks are transient; reconnect obtains committed history, not a cached reconstruction of an unfinished assistant prefix.   |

There is no new Client/wire protocol in this slice. The nine operation rows describe the Host-internal service seam; public transport decoding and its operation inventory must be supplied with A's registration.

History's complete page wait (checkpoint, native read-open/read and reader-close) has a default 15-second deadline; the trusted Host may lower `readTimeoutMs` within 10–15,000ms. An expired wait returns `read-timeout`, and UI/authority/Host-lifetime cancellation returns `cancelled`. This interrupts the request's wait and suppresses late content; it does not claim that shared native flush/I/O stopped or that a Run was stopped. A late successful open is closed without reading its body; a late rejection is consumed, and a failed reader cleanup emits only a constant diagnostic. A close already started is allowed to settle independently. Initial `follow` uses this same bounded read and immediately removes its three listeners on cancellation/timeout. The live subscription also ends on the runtime's own close. Actual stop and Host teardown still require their native idle/durability evidence.

## Native and persistent facts

The mapping schema is version 1, strict and JSON-validated. It contains full scope, native session/Agent ID (one identity in DSH), provider/model selection/configuration ID, and receipt IDs/fingerprints/statuses. Transcript, queue bodies and tool history remain in DSH's native session JSONL. The metadata store is single-open at Host lifetime; asynchronous writes are serialized per locator. No conversation cache or alternative execution state machine exists.

`received` proves native admission and durability; `claimed` proves removal for a proposed step or a native user/message. Neither proves model adoption, successful tools, submission, review or task completion. Queue while idle parks; Queue while running is consumed after the current turn by the native driver. Stop with keepInbox parks it while that Agent is alive. A later explicit followup can wake it; opening, history reads and native cold resume do not wake it.

## Open release gates

### Accepted input reader (component slice)

`registerNativeAcceptedInputTool(agentCtx, binding, grant, service, ports)` returns `{ context, toolAllowlist }` for the existing composition callback. It registers only `read_accepted_input`, in that Agent's unpublished scope. It never creates a member, Run, workspace, execution service, database, model driver, RPC, submit or downstream unlock.

The required Host-owned ports are:

```ts
interface NativeAcceptedInputPorts {
  catalog: {
    scope: NativeWorkScope;
    inputs: readonly { input: UpstreamInputView; required: boolean }[];
  };
  resolveCurrentCaller(signal: AbortSignal): Promise<ExecutionCaller>;
  reader: Pick<ExecutionService, 'upstreamContent'>;
}
```

`catalog` must come from the current authorized Run's frozen inputs, not the initial applied-plan references or a repairing inbox query. It preserves B's visible/pending/hidden distinctions. `required` is an explicit authority fact; it is never inferred from `blocking`. Missing ports, unknown requiredness or a mismatched full scope fail composition. A required pending/hidden source also fails before publication. A known catalog containing only optional unavailable inputs remains visible as metadata and enables no reader tool. The current B projection does not itself supply requiredness or a formal Run context; these are still missing production ports.

Visible handles hash the full actor/space/task/plan/revision/node/Run/generation/segment and exact source-node/version-ID pair. The hash is a deterministic locator across normal reopen, not permission, and no handle database is added. A display version number cannot replace its immutable ID. Model arguments are strictly limited to `inputRef`, `part` (`text`/`links`), `offset` and `limit`. The runtime rejects extra identity, source, path or URL arguments before source I/O. A fresh trusted caller is resolved before each existing B `upstreamContent` call and again after it; all grant/signal checks, caller/space, complete upstream/downstream location, immutable ID and numeric-version echoes must still match.

The initial prompt contains bounded metadata only. Each response returns just the selected part, provenance and `offset/returned/total/hasMore/nextOffset`: at most 4,096 Unicode codepoints or 5 HTTP(S) links, and at most 24 KiB of serialized JSON. Links are never fetched; files are not read or represented as returned bytes. An oversized selected page returns a constant error and can be retried with a smaller range. No whole-input read or complete-file claim is made. The synchronous last-mile finalizer always returns safe content, catches every rejection and does not fall through to the original body. A transient execution-token/digest check rejects a post-policy value replacement; no body cache or extra history ledger is kept.

The existing strict v1 binding gains only optional `{ attempts, chargedBytes }` aggregate counters, capped at 16 admitted body attempts and 64 KiB of conservatively accounted page JSON per unchanged Run/generation/segment binding. Old bindings start at zero. Admitted valid, invalid-argument and unknown-handle attempts are counted; same-owner busy, foreign-owner, exhausted and sealed reservations reject before metadata writes. Calls rejected by native permission guards never read a source. After exhaustion, only constant denial/control output remains available; it is not a model-token or total-denial-message budget. A source read reserves up to 24 KiB before I/O; an unknown, failed, revoked, oversized or abandoned read keeps that full reservation. Only known unused bytes are refunded. A known pre-I/O argument failure charges its bounded error result. Settlement rereads the latest binding in the same per-locator serial queue as send/receipts, preserving concurrent receipt and counter changes. Normal reopen does not reset counters. New Run binding migration remains outside this slice.

Only one actual source promise can be outstanding per native session. The five-second tool deadline ends the caller's wait, not B's underlying queue or I/O. Late success is dropped and late rejection consumed; the slot stays held until the actual promise and metadata settlement finish. Native driver idle is insufficient: `stop` uses one total five-second deadline across native stop and this drain, returning `pending` while the source is held. Normal close seals new reservations, awaits native scope/source drains, then closes the mapping domain. The tool's scope disposer aborts delivery and waits for the source before the native persistence handle is closed.

Actual component testing found that native persistence locking alone did **not** reject another Host in the same process. A small module-local `nativeSessionId → ownerRuntime/drain` map therefore reserves the operational slot synchronously before the first persistence await. Foreign runtime connect/attach and reservation attempts reject while that source is held, with no foreign metadata/receipt/counter writes. The entry is removed only when the actual read settles; nothing is persisted in a second domain. This is a same-module, same-process operation fence, not member authorization, a workspace lease or whole-Host/Run ownership. The two-Host proof uses direct `runtime.connect`, not a fabricated business grant or a new service send. It verifies unchanged mapping-domain bytes as well as the exact binding/receipts/counters.

`native-work-session-input-tool.test.mjs` contains pure port/metadata contracts. `native-work-session-input-tool.spec.ts` must run against the complete fixed native patch; it drives the real Loop's model tool-call/result path with scripted responses, the actual B reader with test-owned memory storage, and contract-only caller/catalog/grants. It covers Unicode/ranges, three metadata-only inputs with one selected source, strict arguments, full source echoes, pre/post-policy revocation, late errors, output caps, total-stop deadline, held-read close/reopen, foreign refusal without metadata writes and persisted attempt exhaustion. It does not certify live member/session resolution, workspace/Run authority, real model quality, file bytes or GUI.

Production mounting is intentionally absent until A/B provide the real ports and formal Run lifecycle. The current formal execution storage does not yet establish these Run/generation/segment/workspace facts; the separate Desk prototype is not authority for this path. Human-assisted submission and an expert node's automatic submission also remain distinct B authorization work. No UUID, member or expert ID is invented here to make that chain appear connected. A owns shared exports/Host assembly and registering the new fixture in the existing native verifier; no A scripts or CI are changed by this slice.

The published DSH baseline clears pending input during normal AgentHandle/Host teardown. A real same-disk characterization test proves the queue existed after stop, then a durable canceled splice and absent native pending item after normal close/resume. That remains a negative baseline, not a product recovery success. The product path requires the actual opt-in lifecycle patch while retaining existing child/setup-failure defaults; unpatched SDKs must not be treated as supporting it.

Creation and resume now consume A's `requireNativeInboxRetention(ctx.agents)` and compatible option types. The actual active factory must advertise strict `retainPendingInboxOnDispose: true`; only then does C pass that same flag at the top level of create/resume. Missing support raises `native-inbox-retention-unsupported` before a native factory call, not a fallback to the published SDK's clearing behavior. Client/model requests cannot choose this policy. Pure open/history do not require or drive a factory. The published SDK's teardown behavior remains an explicit characterization, not the product's recovery path.

The complete A lifecycle patch against fixed DSH has been used to exercise C's actual adapter: the same stopped queued message survives normal close and explicit resume without a model call, explicit removal remains cancellation, and a changed Run generation cannot resume or drive the old preserved queue. Separate write/read processes use the same native message and session IDs with zero scripted-model requests on restoration. These are real native component/storage results with contract grants and scripted responses, not formal member authorization or installed desktop evidence.

`pnpm check` runs old published-SDK rejection/characterization controls and the service fault-injection contracts. The previous 20 production component cases are retained as `native-work-session.spec.ts` and `native-work-session-read.spec.ts`, and the three retention cases plus separate process modes are in `native-work-session-retention.spec.ts`. They must run against the complete actual patch with one native runtime alias; no old package receives a fabricated capability, and no failed test becomes a skip. Native verification requires generating `zhuma-native-work-bundle.ts` from this package's real fixture/adapter and copying these specs into the fixed runtime tree; the current native evidence uses that temporary preparation. A owns registration in the existing native-lifecycle entry, still pending at this handoff. These fixture runs are separate from the root Node-suite totals.

This slice rejects mismatched Run/generation/segment and selection. Explicit new-generation binding/segment handoff, formal B grants/Run lifecycle and automatic fixed submissions, controlled input/file tools, independent Agent review, directed inter-session messages, model quotas/time limits and normal Client integration remain required follow-up work. No default infinite retry or model loop is added here. Existing receipts reach a declared capacity rather than being silently evicted.

Tests use real published native services, real JSONL/storage-domain and scripted in-process model responses. Grant/race fault injection is separately labeled contract coverage. These do not certify real model quality, installed desktop bytes, member authorization assembly, file bytes or GUI behavior. No paid model is called.
