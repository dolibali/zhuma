# Native work session seam v1

## Read-only inbox and public conversation observation

The following C-owned APIs are Host-internal and need A's normal authorized transport/UI integration. They do not replace the native transcript or add a chat database.

```ts
service.readInbox(grant, signal?) // history permission, no native admission
// { binding, asOfSeq,
//   receipts: [{ requestId, messageId, mode, status: 'received' | 'claimed' | 'unknown' }],
//   items: [{ id, text, target: 'next-turn' | 'next-step', requestId, mode, status: 'received' }] }
service.observe(grant, after = -1, signal?) // follow permission
// AsyncIterable<{ scope, nativeSessionId } & NativeConversationFrame>
```

`readInbox` opens the official persistence handle with `read` access, then uses the official `sessionProjections.restore` and its registered inbox unit at a single contiguous cut. Each page rechecks current scope, permission, persistence instance and projection source. It neither creates/resumes an Agent nor appends an event or a product binding. A live session may flush its already-committed native events before reading; this is not a send/wake. Cold/terminal reads use the same persisted inbox. A missing projection is `unavailable`, not an empty success. An unmaterialized binding with no receipts can return the explicit empty cut `asOfSeq: -1`.

Only textual user-origin items whose native IDs match this binding's request receipts enter `items`; runtime/system/foreign inbox work remains private. `received` means present in the official pending inbox. `claimed` requires the exact native `user/message` fact at this same cut; it is **not** proof that the model obeyed or adopted the message. Absence alone is `unknown`, never claimed/discarded. The existing queue command path remains the explicit edit/remove/reorder mechanism. Readers must not clear a received item solely because a separate, earlier history page omitted it: catch history up to `asOfSeq`, reconcile by message ID, and keep unknown delivery explicit. Sending another followup after a queued next-turn item can legitimately cause two native turns, one per input; a read/refresh causes none.

`observe` is the presentation whitelist over the existing native observer. It emits only user/model textual messages, necessary tool names, native idle/running, and validated assistant start/chunk/end frames. No raw event, reasoning block, tool arguments/results, provider replay, system/runtime context or credential structure enters this API. Existing raw `history/follow` remain Host-internal diagnostic/source interfaces and must not be forwarded as public conversation data.

Frames carry the complete authorized scope and native session ID. The runtime accepts live publications from the exact attached Agent/session object and unchanged registry/persistence source, not another object reusing its ID. Each read/listener publication and delivered frame checks the original current read grant; the old drive grant cannot grant a new read. Observation does not retarget a replacement Agent or another Run generation. Native attempt ID, monotone revision and dense original index gate live frames. Filtered native chunks still advance the original index; public indices may therefore have gaps. A missing start/index or another attempt produces `gap` at the last durable cursor, not a fabricated prefix.

Each exact Agent scope captures only its current visible attempt before the first model request. A new observer first subscribes, reads durable history, then takes a synchronous `assistant-stream` opening `snapshot` and revision cut before draining newer frames. The snapshot contains `revision` and optional `activeAttempt: {attemptId, startedAfterSeq, nextIndex, text, toolNames}`. The cursor and dense next index are native values; the text and distinct tool names pass the existing presentation whitelist before retention. No reasoning, tool arguments/results or raw provider chunk is cached. Queued stream revisions through that cut are represented or settled by the snapshot and are not repeated. A snapshot without an active attempt clears only transient presentation, not durable messages. Original committed message keys/sequences replace the partial prefix. This is process-local reconnect presentation, not a replay of missing native frames or cross-process recovery of an unfinished attempt.

The visible text stays within the original 262,144-byte budget, names within the original 128-name bound, and the entire encoded snapshot must fit the original frame limit. Capacity or incomplete continuity produces explicit `gap`/failure, never a truncated successful prefix. A new real attempt can recover an over-budget previous prefix. Agent scope disposal, source replacement and revocation release the prefix; aborting only an observer releases its listeners and leaves the Agent and its current prefix alive.

`messageKey = nativeSessionId + ':seq:' + seq` joins a committed end to the one durable message. The durable event commits before the official end frame; consumers replace the transient attempt using that key rather than appending a second message. `assistant/attempt` settlement explicitly indicates there is no surface message; an interrupted `assistant/message` preserves `interrupted: true`. Neither terminal model output nor this read API submits a product artifact or unlocks a node.

At most eight actual native readers and sixteen observers are admitted per runtime; cancelled readers retain their slots until native close settles, and observer abort releases its slot immediately. Inbox replay is bounded to 100 pages of 100 native events, 8 MiB scanned JSON, the configured 10–15,000 ms read deadline, and 262,144 bytes of pending items. Exceeding a bound fails explicitly; no truncated empty inbox is returned and no read checkpoint is written back. Observation retains the existing 128-frame/524,288-byte queue and 262,144-byte frame bound, plus at most 128 distinct tool names per attempt. Overflow returns a durable cursor gap. Abort/close removes listeners immediately even if a consumer is paused on a yielded frame. Caller cancellation/deadline ends the wait, while actual open/read/close work stays owned until the original native resource settles; runtime shutdown drains it before releasing the domain.

`native-work-session-view.test.mjs` is synthetic projection-contract coverage. `native-work-session-stream.spec.ts` runs the actual full patched SDK with a local ScriptedAdapter and contract Run grants: pending/claimed/Stop/cold reads, visible partial text before completion, keyed final history, source-object isolation, old generation/revocation, missing projection and held-reader shutdown. Its separate write/read process modes prove durable inbox restoration without an Agent or model request. A must register this new spec and its two process modes in the native verifier; a temporary runner can exercise the exact current production bundle with one official SDK alias before that registration lands. These tests do not certify real member issuance, HTTP/UI, a real model or the complete #35 scope.

Scope: #35's first Host-internal native session slice. `openNativeWorkSessions(ctx, options)` opens one `zhuma_native_work_sessions` storage-domain and composes the public DSH 0.2.1-rc.2 AgentRegistry, Agent, session persistence and event services. It does not mount RPC routes, establish a member identity, create an Execution Run, submit an artifact, or replace the Agent factory. The normal member transport and shared exports belong to A; Run state and authorization belong to D/B; fixed submission belongs to B.

## Authority and composition

B must establish a Run through the existing execution facts on an explicit, idempotent begin. A Client never supplies a new authoritative Run ID. An existing Run produces `NativeWorkGrant`: trusted `actorId/spaceId/taskId/planId/revision/nodeId/runId/generation/segmentId`, an authority-lifetime abort signal, and synchronous `assertCurrent(action)`. The grant is an internal capability, never JSON supplied by a Client or model. It must validate actual member, space, node, Run and segment facts for the requested operation. Missing authorization must reject; no owner fallback exists in this module. Native session IDs and metadata are not capabilities.

Every service operation checks authority; awaited operations and each emitted frame recheck it. Revocation aborts active native work and prevents late frames reaching the caller. UI read/stream cancellation has a separate signal and does not cancel the Agent. The scoped native pre-step, request and tool gates also check current execution authority. A scoped request may not silently switch the provider/model bound to the Run.

`options.compose(agentCtx, binding, grant)` runs in the unpublished native scope. It returns a bounded necessary-task context and the exact allowed tool names; an empty allowlist disables tools. DSH's restriction API accepts inherited/global tools only, so the adapter passes only actual global names to that mask. Scope-owned tools remain registered locally. A monotonic execution guard enforces the complete declared allowlist and current grant; publication and each pre-step also check that the actual scoped tool surface exactly matches it. An unexpected scoped registration fails publication instead of being silently exposed. A supplies authorized goal and fixed-reference metadata and composes resource tools here; skill/MCP/resource authorization is not integrated by this slice. It adds no source body by itself. Composition failure or stale authority rolls native publication back.

There is no new Client/wire protocol in this slice. The nine operation rows describe the Host-internal service seam; public transport decoding and its operation inventory must be supplied with A's registration.

History's complete page wait (checkpoint, native read-open/read and reader-close) has a default 15-second deadline; the trusted Host may lower `readTimeoutMs` within 10–15,000ms. An expired wait returns `read-timeout`, and UI/authority/Host-lifetime cancellation returns `cancelled`. This interrupts the request's wait and suppresses late content; it does not claim that shared native flush/I/O stopped or that a Run was stopped. A late successful open is closed without reading its body; a late rejection is consumed, and a failed reader cleanup emits only a constant diagnostic. A close already started is allowed to settle independently. Initial `follow` uses this same bounded read and immediately removes its three listeners on cancellation/timeout. The live subscription also ends on the runtime's own close. Actual stop and Host teardown still require their native idle/durability evidence.

## Native and persistent facts

The domain layout remains version 1. Binding rows accept the unchanged strict flat-v1 record or the strict timeline-v2 record described below. It contains full scope, native session/Agent ID (one identity in DSH), provider/model selection/configuration ID, and receipt IDs/fingerprints/statuses. Transcript, queue bodies and tool history remain in DSH's native session JSONL. The metadata store is single-open at Host lifetime; asynchronous writes are serialized per locator. No conversation cache or alternative execution state machine exists.

`received` proves native admission and durability; `claimed` proves removal for a proposed step or a native user/message. Neither proves model adoption, successful tools, submission, review or task completion. Queue while idle parks; Queue while running is consumed after the current turn by the native driver. Stop with keepInbox parks it while that Agent is alive. A later explicit followup can wake it; opening, history reads and native cold resume do not wake it.

## Open release gates

### Accepted input reader (component slice)

`registerNativeAcceptedInputTool(agentCtx, binding, grant, service, ports)` returns `{ context, toolAllowlist }` for the existing composition callback. It registers only `read_accepted_input`, in that Agent's unpublished scope. It never creates a member, Run, workspace, execution service, database, model driver, RPC, submit or downstream unlock.

The required Host-owned ports are:

```ts
interface NativeAcceptedInputPorts {
  catalog: {
    scope: NativeWorkScope;
    inputs: readonly { input: UpstreamInputView; required: boolean }[];
  };
  resolveCurrentCaller(signal: AbortSignal): Promise<ExecutionCaller>;
  reader: Pick<ExecutionService, 'upstreamContent'>;
}
```

`catalog` must come from the current authorized Run's frozen inputs, not the initial applied-plan references or a repairing inbox query. It preserves B's visible/pending/hidden distinctions. `required` is an explicit authority fact; it is never inferred from `blocking`. Missing ports, unknown requiredness or a mismatched full scope fail composition. A required pending/hidden source also fails before publication. A known catalog containing only optional unavailable inputs remains visible as metadata and enables no reader tool. The current B projection does not itself supply requiredness or a formal Run context; these are still missing production ports.

Visible handles hash the full actor/space/task/plan/revision/node/Run/generation/segment and exact source-node/version-ID pair. The hash is a deterministic locator across normal reopen, not permission, and no handle database is added. A display version number cannot replace its immutable ID. Model arguments are strictly limited to `inputRef`, `part` (`text`/`links`), `offset` and `limit`. The runtime rejects extra identity, source, path or URL arguments before source I/O. A fresh trusted caller is resolved before each existing B `upstreamContent` call and again after it; all grant/signal checks, caller/space, complete upstream/downstream location, immutable ID and numeric-version echoes must still match.

The initial prompt contains bounded metadata only. Each response returns just the selected part, provenance and `offset/returned/total/hasMore/nextOffset`: at most 4,096 Unicode codepoints or 5 HTTP(S) links, and at most 24 KiB of serialized JSON. Links are never fetched; files are not read or represented as returned bytes. An oversized selected page returns a constant error and can be retried with a smaller range. No whole-input read or complete-file claim is made. The synchronous last-mile finalizer always returns safe content, catches every rejection and does not fall through to the original body. A transient execution-token/digest check rejects a post-policy value replacement; no body cache or extra history ledger is kept.

The existing strict v1 binding gains only optional `{ attempts, chargedBytes }` aggregate counters, capped at 16 admitted body attempts and 64 KiB of conservatively accounted page JSON per unchanged Run/generation/segment binding. Old bindings start at zero. Admitted valid, invalid-argument and unknown-handle attempts are counted; same-owner busy, foreign-owner, exhausted and sealed reservations reject before metadata writes. Calls rejected by native permission guards never read a source. After exhaustion, only constant denial/control output remains available; it is not a model-token or total-denial-message budget. A source read reserves up to 24 KiB before I/O; an unknown, failed, revoked, oversized or abandoned read keeps that full reservation. Only known unused bytes are refunded. A known pre-I/O argument failure charges its bounded error result. Settlement rereads the latest binding in the same per-locator serial queue as send/receipts, preserving concurrent receipt and counter changes. Normal reopen does not reset counters. New Run binding migration uses the explicit phased protocol below; it cannot reset a budget on the same Run.

Only one actual source promise can be outstanding per native session. The five-second tool deadline ends the caller's wait, not B's underlying queue or I/O. Late success is dropped and late rejection consumed; the slot stays held until the actual promise and metadata settlement finish. Native driver idle is insufficient: `stop` uses one total five-second deadline across native stop and this drain, returning `pending` while the source is held. Normal close seals new reservations, awaits native scope/source drains, then closes the mapping domain. The tool's scope disposer aborts delivery and waits for the source before the native persistence handle is closed.

Actual component testing found that native persistence locking alone did **not** reject another Host in the same process. A small module-local `nativeSessionId → ownerRuntime/drain` map therefore reserves the operational slot synchronously before the first persistence await. Foreign runtime connect/attach and reservation attempts reject while that source is held, with no foreign metadata/receipt/counter writes. The entry is removed only when the actual read settles; nothing is persisted in a second domain. This is a same-module, same-process operation fence, not member authorization, a workspace lease or whole-Host/Run ownership. The two-Host proof uses direct `runtime.connect`, not a fabricated business grant or a new service send. It verifies unchanged mapping-domain bytes as well as the exact binding/receipts/counters.

## Explicit Run segment handoff

This is a C-owned component slice of #35/#113, not a second Run state owner. D's canonical phased authority is structurally consumed without importing D's in-flight implementation:

```ts
interface NativeRunMigrationGrant {
  requestId: string; // D's new attempt.idempotencyKey
  inputFingerprint: string; // D's new attempt.payloadHash, SHA256
  previousScope: NativeWorkScope;
  scope: NativeWorkScope;
  selection: NativeSessionSelection;
  signal: AbortSignal;
  assertCurrent(phase: 'prepare' | 'migrate'): void;
}
```

D derives every field from the same current persisted node/old-new pair, authenticates the original MemberRequest, checks old terminal/resource facts and current membership/controller/config/workspace, and owns the authority object's receiver identity. C always invokes `grant.assertCurrent(phase)` on that exact object: no function extraction, copied grant, reconstructed member or drive/read/cleanup grant substitutes for it. Same actor/space/task/plan/revision/node, a different Run and segment, and strictly increasing generation are required. A reassignment or skipped unbound attempt is not silently adopted.

The two phases avoid a cleanup/permission cycle. Initial issuance and `prepare` authorize only cleanup of the exact old scope; they do not claim that C is already drained. `migrate` additionally obtains D's optional Source `migrationDrain(previousScope)` and binds its actual ready epoch. C provides the read-only producer as `service.migrationDrain(scope)`. Missing/not-ready evidence rejects the mapping advancement. The Source adapter may return undefined only for the explicit `migration-not-ready` code; storage, scope, ownership, service identity and cleanup failures must remain errors. The producer must retain the same function identity, and C returns the same signal within each ready epoch. A remains the Host/transport/exports owner. B/D remain the single Run writer and permission producers. No public RPC is mounted here.

These four operations are Host-internal, not wire DTOs. Their concrete contracts are:

### Observing the actual migration origin

D's durable history may contain an intermediate Run that failed before C ever established its native binding. The neighboring Run is then not the native origin. `migrationOrigin` reads this same C service's existing row; it neither manufactures the missing Run's binding nor treats a persisted settled label as a native fact. Request IDs/strings retain the existing 200-character bounds, input hash remains SHA-256, and full scope/selection validation is reused. Results contain exactly the old scope and old frozen selection, with no native IDs, receipts, budgets, chat, grant or signal.

For an uncommitted request, the real current binding is the candidate and must form a valid advancing pair with the new requested scope. For a committed same-key retry, lookup uses the prior migration receipt and verifies its input hash and full pair/selection fingerprint, plus exact new current scope; the result is the original previous binding, never the already-new current binding. Wrong key/hash/selection, a later current segment or malformed lineage refuses. An unseen prospective key/hash is not certified by C; D must derive it from the authorized persisted new Run.

Missing rows throw `not-started`; malformed data throws `binding-state-invalid`; incompatible input retains the existing scope/idempotency/conflict errors. Unknown mapping writes retain `migration-unknown`. Sealed lifetime, admitted mapping/source/native mutation, active native model work, foreign owner or failed/unfinished native cleanup refuses with an error. Origin lookup does not turn these into undefined or `migration-not-ready`. A cold/never-prepared native epoch may be observed as metadata only; if this service already owns preparation that remains physically pending, origin refuses until its actual native barrier settles. This uses existing service/runtime observations and adds no storage layout, resource driver or persistent facts.

D authenticates the original member and new node before lookup, then validates and pins the entire persisted Run vector from the returned old scope through the new current Run, with all intervening attempts terminal and resource-settled as required by D. It pins the producer identity and checks its own permission/history facts on every phase. It does not re-enter origin lookup from C's own migration metadata slot, which must reject in-flight queries. The canonical grant's `previousScope` remains unchanged. C's independent prepare/current/replay/fingerprint/physical-barrier checks still run after this observation; the origin is not a permission and does not certify whole-Host or direct driver activity outside the service.

The follow-up adds four origin/failure contracts to the existing migration Node tests and five real patched-native origin cases in `native-work-session-origin.spec.ts`. The original 47 native cases remain unchanged. Actual D skipped-history authority and fresh-process linkage are D's independent integration responsibility; B member/workspace issuance and A Host/Client/public exports remain separate.

### Actual readiness and cold cleanup

An idle Agent or `resources:'settled'` string alone is insufficient. Runtime retirement tracks in-flight create/dispose work, cancels and awaits the real old Agent, flushes it, closes its scope/writer, then explicitly write-opens the **existing** native log, flushes and closes it. A cold Host performs that same real barrier only under `prepare` authority, without creating/resuming any Agent or registering tools. History only opens read handles and never invokes preparation. A missing log is accepted solely when C's binding has no admission receipts and the real backend returns NotFound; its evidence is separately labeled `absent-unadmitted`, not flushed-and-closed. A missing log with receipts, foreign/unknown owner, malformed format or failed flush/close refuses. An unconfirmed writer close remains tracked and fenced; Host close retries its owned handle but does not turn the failed preparation into a successful readiness receipt. Unknown owner failures can require fresh-process reconciliation; they are not silently forgotten or auto-retried as new writers.

Native persistence identity is the SDK's public stable symbol. Cordis service lookup returns fresh trace proxies, so raw proxy `===` is not a valid registry identity; the public `Service.tracker` metadata identifies the actual registry instance through those proxies. Real native testing caught the proxy comparison failure before replacing it with that stable identity check. Readiness rechecks service identities and actual live handles; D's source lifetime/replacement invalidation remains necessary. Native resource epochs are process-local owner observations, not member, workspace, Run or cross-process authority. Another runtime's actual restore invalidates the old signal; unknown cleanup keeps its owner fenced. Whole-Host/other-tool/background-resource quiescence is not inferred from this component lease.

C separately tracks admitted old-scope send/queue work and source promises. It does not count its own prepared mapping commit as external activity, avoiding the D-readiness/self-queue deadlock. Input-read refunds still run in the original queue; preparation waits them without occupying that queue. A pending wait has no new mapping or late automatic migration. An old-scope mutation or restoration after readiness invalidates that epoch; acquire a new D capability/ready epoch, not a copied or previously bound stale grant.

### Storage, recovery and history

The same `zhuma_native_work_sessions.bindings` row is either the existing strict flat-v1 binding or:

```ts
{ schemaVersion: 2, version, current, prior: [
  { binding, migration: { requestId, inputFingerprint, fingerprint } },
] }
```

`version` is **total segments**, equal to `prior.length + 1`, from 2 to 64. Total serialized row size is at most 2 MiB. Capacity refuses before writing; no entry is evicted. Each old binding retains its full scope, native IDs, selection, message receipts and aggregate input budget. New current starts with empty receipts and a new budget; new native IDs differ. Pair order, monotonic generations, all locator fields, unique Run/segment/native IDs/request IDs, pair hashes and the count are validated. A truncated, duplicate, incomplete, future or oversized record fails closed. Every later send/receipt/refund writes only `current` while retaining `prior` in that same put.

The pinned JSON single layout does not implement domain-version migration through `compatibleVersions`; this slice keeps the domain version and global unchanged. Old strict flat-v1 schemas refuse the new row on cold reopen with no byte changes. Actual published JSON storage tests cover legacy read-without-write, strict old refusal and full new reopen. This is not protection from an already-running old Host or another process holding its own stale backend. Deployment still requires the agreed single Host writer; no downgrade deletes the new history references.

Crash ordering is explicit: D persists the pair before any C effect. If C still holds old, a fresh authorized explicit migration prepares and writes that pair; if C already holds new, it returns the same recorded IDs. Once a mapping put is admitted, an error is unknown and fences the live key; drain/close/reopen must reveal the actual record before retry. No cross-domain atomic transaction is claimed. D records C references as locators, not native received/accepted; the first explicit send creates/adopts only the new segment and supplies real admission separately. Normal open/refresh/history never reconciles by dispatching or replaying send.

Existing `open/history/follow` resolve only the matching authorized current or archived scope. Drive/queue/stop never choose an archived binding. D issues a separate current-permission read grant for a historical Run; a new Run's drive grant does not grant old history. An unmaterialized segment with no receipts returns an empty read without creating a log; missing admitted history is an error. Old native queue bodies remain in that old DSH segment and are never copied into the new prompt, replayed, or driven by the migration. One Run can have many native turns; a new Run alone creates a new segment.
